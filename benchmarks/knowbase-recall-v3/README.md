# 召回能力评测集 v3

本集用于继续排查召回，不评判回答生成。158 篇合成 Markdown，224 道题，全部保留来源文档名与原文证据。用户未提供真实问题，因此新增内容全部由助手生成，业务规则与数字均为虚构；不能标为真实用户数据、独立人工标注或生产验收。

| 分组        | 题数 | 可回答 / 无答案 | 来源                         |
| ----------- | ---: | --------------: | ---------------------------- |
| regression  |   80 |          72 / 8 | v2 原题，之前已经测量和查看  |
| development |   96 |         72 / 24 | 新增 8 个业务主题、16 篇资料 |
| validation  |   48 |         36 / 12 | 另外 4 个业务主题、8 篇资料  |

语料包含原来的 134 篇（14 篇项目资料与 120 篇模板干扰），新增 24 篇现行规则及例外/历史对照资料。开发与验证的 gold 文档及业务主题互不交叉，所有文档均进入索引，因此检索仍面对相邻业务的干扰。题型和资料结构仍采用相似模板，source-family 分开只能减少同事实改写泄漏，不能消除模板相关性或替代真实用户盲测。

每个新增业务主题有 9 类正样本各 1 题：精确标识、同义口语、否定与前置条件、数字边界、角色与访问范围、标题依赖、多文档、历史规则、跨 Chunk。另有 3 类负样本：资料未规定的数值、没有记录的接口资料、要求不存在的允许条款。最后一类可以通过纠正前提解释“没有允许条款”，所以无答案意为没有题目所要求的正向事实，不等于没有相关文字；本工具只记录候选，不评判拒答或纠错质量。

12 篇现行规则特意包含较长章节；标题依赖题的数字证据与对应标题会被当前 1000/150 分块分离。跨段落题的两条证据也确实分处不同 Chunk，结构由 API 的真实分块器测试检查，不只是给题目贴标签。原文与证据冻结后不根据模型得分调整。

冻结计数、覆盖要求、开发/验证来源隔离及候选预算对照见 `protocol.json`。`coverage.json` 是校验器生成的题型与来源清单。校验会拒绝：缺失原文证据、来源串组、同题重复、计数不符、缺少负样本原因、合成来源标识缺失和关键题型缺席。

```bash
python tools/rag-evaluation/benchmark_dataset.py benchmarks/knowbase-recall-v3 \
  --coverage-output benchmarks/knowbase-recall-v3/coverage.json
```

先用 development 比较配置，冻结方案后才运行 validation；旧 regression 可独立重跑。随着验证结果被查看或用于优化，该组就变成回归资料，后续验收必须另建未用于调参的问题。v1/v2 原文件保持不变。

当前开发预算矩阵及一次固定配置验证已经完成，结果见[预算对照报告](experiments/budget-audit-v3.md)。30:10 提升了总体候选池召回，但验证组标题依赖题未通过门槛，线上预算保持现行配置。本组 validation 已被查看，后续使用需按已暴露的回归资料处理。

后续[标题与章节对照](experiments/context-audit-v3.md)已对全部 224 题执行三种上下文、三对预算，共 2016 次计分。开发组标题加章节在 10:10 即达到 100% 池证据召回，15:15 的最终证据为 54.86%；旧回归仍有个别池证据退步，默认模式保持正文。原文 Chunk、语料指纹与模型摘要已逐轮核对一致，辅助文本不作为引用证据。

针对上述退步，[正文保护对照](experiments/body-protection-audit-v3.md)完成 4 种配置 × 2 对预算 × 224 题，共 1792 次计分。候选选型、逐证据比较、预算边界及成本见该报告和同目录 decision/results JSON；默认配置仍未自动切换。正文候选恢复与最终 Top 5 选择分开记录，不能把池证据命中直接当作回答正确。

随后[候选边界对照](experiments/recall-boundaries-audit-v3.md)完成 1120 次计分：区分安全复查与预算截断，保留 2:1 比例，实验预算候选为关键词 30 / 向量 15。旧题池证据提高但最终选择未提高，默认及 HTTP 规则未变；无效比例和简单术语追加均记录后停止，没有覆盖先前历史报告。

最新[多意图查询对照](experiments/multi-intent-audit-v3.md)完成 3 模式 × 224 题，共 672 次计分；固定 30:15，保留原问题并测试提取子句。没有新增池证据，仍有最终证据退步，故不采用、保持不拆解；工具和逐证据结果保留用于复核，业务查询未改。

后续[关键词降噪对照](experiments/keyword-noise-audit-v3.md)完成 2 模式 × 224 题，共 448 次计分；134 题实际删除疑问词，但各阶段标注证据无新增或丢失，故不采用、保持原问题。独立重建也带来未改动查询的候选波动，未宣称 Precision 或排名收益；原始证据、限制和停止决策见报告。

[标识符与短语优先匹配](experiments/phrase-match-audit-v3.md)采用同索引交替三模式、两遍：本语料 1,344 次，加独立专门样本 60 次，共 1,404 次计分。没有证据或关键词前 5 条收益，两道旧题关键词排名退步；控制组稳定，故不采用并停止细调。报告包含分词符号/大小写碰撞和专门样本的上限，不把这些合成测量推广为完整 Precision 或验收。

预算实验示例：

```bash
pnpm --filter @knowbase/api benchmark:retrieval \
  --python "$PWD/.venv-rag-eval/bin/python" \
  --suite recall --dataset benchmarks/knowbase-recall-v3 \
  --split development --encoding plain --lexical cjk \
  --route-budgets 5:5,5:15,10:10,15:5,10:15,15:10,15:15,10:30,30:10 \
  --output-dir reports/retrieval-recall-v3-budgets
```

每对为“关键词路保留数:向量路保留数”，最终选择仍固定 Top 5；原始索引读取上限仍为各路保留数的 3 倍、最多 100，不能混淆这两个数量。不同分配分别实际检索，没有拿大预算结果离线裁剪来假装多轮实测。原有 `--budgets` 等额矩阵继续兼容，与新参数互斥。业务 HTTP 候选策略不随实验改变。
