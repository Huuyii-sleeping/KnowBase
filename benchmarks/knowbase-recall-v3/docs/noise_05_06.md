# 模拟业务：库存盘点的年度归档检查

这是评测专用的模拟业务资料，编号 OPS-05-06，用于检验相似主题干扰。该资料描述业务人员的操作制度，不描述 KnowBase 软件内部实现。

本记录适用于库存盘点。年度归档检查由业务专员负责登记，复核人为该业务的主管。每项申请都关联独立的业务编号，申请编号与资料文件名不能混用。主管批准的是业务申请，资料发布只是把处理结果告知申请人，不能用资料上传成功替代业务批准。

## 年度归档检查的输入与输出

申请人先上传库存盘点相关的附件，再在业务表单填写用途、所属部门、办理日期和联系方式。系统列表显示申请摘要，打开详情后可阅读附件说明。表格中的业务金额和数量必须人工核对，资料中出现相同标题不表示它们是同一条申请。附件缺页时，业务专员应通知申请人补充材料。

业务专员收到材料后记录当前处理阶段。存在材料不全、信息冲突或者超过预算的情况时，申请会退回修改。申请人重新提交后应保留上一次退回意见，避免审核人员重复询问。这里的草稿、待审、批准和驳回都是业务表单的处理状态，不能据此推断知识库的文档状态。

## 库存盘点的异常与追踪

若通知消息延迟，业务专员应先核对申请编号，再确认通知是否已经发送。重复通知不能作为重复办理的依据。附件链接无法打开时，先确认接收人的查看权限和文件是否完整，记录发生时间并联系业务主管。此流程没有规定 RabbitMQ、Outbox、向量索引或数据库表的实现方式。

同一项库存盘点可以产生不同时间的业务说明。历史版只用于查阅当时的办理经过，当前业务结论以本次主管签署的处理记录为准。业务档案保管人在每季度核对单据与附件的关联，不得根据文件名猜测申请人的身份，也不能把测试样例当作真实审批结果。

## 检查清单 OPS-05-06

检查库存盘点资料时依次确认：业务编号正确、附件可阅读、申请部门一致、主管意见齐全、处理日期已填写、申请人能够看到当前结果。所有数字均为模拟业务示例：本批次建议在 7 个工作日内完成登记，复核人数为 2 人。清单没有解释文件解析器、Embedding 模型、索引批次或图谱查询算法。
