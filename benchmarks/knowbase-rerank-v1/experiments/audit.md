# 固定候选池的首轮重排诊断

RRF 在本轮合成回归中的总体证据覆盖提高，但丢失了原规则已选中的十条证据，没有通过事先冻结的“无新增证据损失”门槛。因此不替换业务规则，也不继续据此细调 RRF 常数。简单文本多样性、去掉双路奖励及放宽约束的结果也已保留；下一轮值得独立比较专用重排模型，而不是继续改召回。

后续[逐题语义复核](semantic-review.md)发现：十条标注损失中，4 条仍有配套文档的等价依据、1 条权限依据不完整、5 条确实缺少所问的撤回时长和起算点。本报告下文的“退步”均指冻结的标注证据指标，不代表已经验证十道题的最终答案变差；原评分和决策文件不变。

## 隔离变量与复现

代码、来源指纹、参数和门槛先提交冻结为 `c18b720`（完整执行提交以 [results.json](results.json) 为准），之后才对替代方案计分。使用已有真实接入产生的候选记录：v3 原查询 224 题、旧新来源默认 80 题、旧新来源候选 80 题，共 **384 份来源–问题候选池 × 9 方案 = 3,456 次离线选择**。不同检索配置重复使用了那 80 道新来源题，跨数据集共 304 个不同题目 ID，不是新增 384 道独立问题或 3,456 次在线检索。

各来源的原文、问题、模型、配置、候选顺序、Chunk ID、路由分数均冻结；原查询、两路结果与合并池不变，不重新上传或查索引。读取前检查已完成状态、原始解压字节/元数据/索引快照与语料的 SHA-256。当前应用构建产物重建的合并池及原规则 Top 5 的**完整对象、分数与顺序**与历史结果逐条完全一致；全部 384 题通过后才比较方案。诊断选择器也与真实 RerankService 对齐，保留首个超长片段的既有例外。

这是固定池的离线控制实验，不能代替接口、运行时权限、并发或答案评测。语料都是助手合成、先前已暴露；holdout 一词只表示来源目录的历史名字，本轮没有新的盲测。不同来源的池也不同，比较在每个来源内部进行，不把两套候选池的差异归因于重排。

## 先看证据在哪里丢失

原规则在池内找到、最终未选出的证据共 162 条来源–题目–证据实例：v3 开发 41、旧题 45、已暴露验证 16、新来源默认 38、新来源候选 22。相同证据在两套新来源配置中可能重复计数。

这些证据所在候选到达选择器时，都已填满最终 Top 5，记录为 `top_k`。这是执行时的跳过理由，不单独证明 Top K 数值就是根因；前面已选择的内容、同文档限制和打分共同影响顺序。为了验证，另做约束消融：

| 只改变的限制 | v3 开发证据 | v3 旧题证据 | v3 已暴露验证证据 | 新来源默认 / 候选 |
| --- | ---: | ---: | ---: | ---: |
| 原规则：Top 5、每文档 2 块、6000 字符 | 56.25% | 48.61% | 65.28% | 50.00% / 71.09% |
| 每文档上限改 5 | 不变 | 不变 | 不变 | 不变 |
| 字符预算改 12000 | 不变 | 不变 | 不变 | 不变 |
| 最终数量改 Top 10 | 64.58% | 51.39% | 70.83% | 不变 |

扩大 Top K 有部分收益，却仍缺证据，而且改变了返回数量，不能和 Top 5 当作同预算选型。直接放宽同文档或字符限制没有本轮证据收益；不据此继续增大。这支持先检查排序本身，也不表示这些限制在所有语料都没有作用。

## 同预算比较：规则与 RRF

除上述诊断消融外，方案统一保持 Top 5、每文档最多 2 块、6000 字符上限。现有规则仍使用语义 0.5、关键词 0.25、字词覆盖 0.15、双路奖励 0.1。RRF 用保留候选的原路由名次求 `1/(60+keyword_rank) + 1/(60+semantic_rank)`；某路没有命中则不贡献，不使用金标、问题关键词特判或原始分数量级。

| 来源 / 分组 | 原规则证据召回 | RRF 证据召回 | RRF 新增 / 丢失证据 |
| --- | ---: | ---: | ---: |
| v3 开发（96 题） | 56.25% | 69.44% | +21 / -6 |
| v3 旧题（80 题） | 48.61% | 77.08% | +25 / 0 |
| v3 已暴露验证（48 题） | 65.28% | 68.06% | +6 / -4 |
| 新来源默认池（80 题） | 50.00% | 92.97% | +31 / 0 |
| 新来源实验候选池（80 题） | 71.09% | 92.19% | +15 / 0 |

证据指标仅对可回答题宏平均；新增/丢失按逐条标注证据实例计算。没有穷尽相关性标注，因此不宣称完整 Precision。RRF 总计新增 98、丢失 10 个实例，不能只报告净增或平均分。

RRF 是冻结的三个可选替代方案中开发组表现最高的候选，开发提升约 13.19 个百分点，超过预设 2 个百分点门槛。但开发组丢六条、已暴露验证丢四条，未通过所有分组无新增损失门槛。没有用验证分数改选其他方案、调常数或追加题型规则。门槛与决策见 [protocol.json](protocol.json)、[decision.json](decision.json)。

原规则还有一个需要后续重点检验的结构：只走关键词的片段，归一化关键词项最多贡献 0.25、字词覆盖最多 0.15，没有双路奖励，总分最高为 0.4；只走向量的片段，仅语义项就可能接近 0.5。这解释了为何“关键词已经找到证据”仍可能排不过大量向量候选。它不是对全部失败题的单一归因；去掉双路奖励的实测也未修复本轮证据损失，后续应比较更能判断问题与正文关系的排序方式。

十条退步分别来自口语改写 4、标题上下文 5、角色范围 1，逐题 ID 与证据下标保存在决策 JSON。例如合同用印的最终批准者、撤销窗口等原先选中证据在 RRF 下落选。此前舞台吊杆问题的“交技术总监复核”在原规则中排名第 16、未入 Top 5，RRF 能选回；修复这一题不能抵消另十条退步。

## 其他方向与停止结论

| 方向 | 结果 | 本轮决定 |
| --- | --- | --- |
| 只去掉双路 0.1 奖励 | 各分组证据无增减 | 无收益，停止这一消融的细调 |
| 文本多样性 | 按 `0.85 × 原规则分 - 0.15 × 与已选正文的最大三字片段 Jaccard` 贪心选择，只找回一道开发题的一条证据；开发证据 56.25%→57.64%，其余不变 | 未达冻结的 2 个百分点门槛；该次实现计算量也更高，不采用 |
| 关键词一路优先，再用向量独有候选补尾 | 新来源池证据可达 98.44%，但全来源共新增 18 条证据损失，尤其标题/历史规则题 | 仅诊断控制，不参加选型；不能因某批关键词很强而移除向量 |
| 向量一路优先，再用关键词独有候选补尾 | 所有分组都有证据损失，无新增证据 | 仅诊断控制，不采用 |

多样性使用正文三字片段，不等同于语义 MMR，也没有单独评测完整近重复率。原始规则高排位并不表示它理解了批准角色、否定或时间边界；这些仍需专用重排模型与相关性标注对照验证。没有安装或调用专用模型，也没有用 Embedding 或 0.5B 聊天模型代替 Cross-Encoder 后声称完成模型评测。

离线工具保存选择耗时。简单规则/RRF 的本轮选择与诊断 P95 多为 0.01–0.03 ms，多样性约 1.55–11.21 ms；统计不含共同的生产规则打分，也含诊断开销，且为单次串行观测。它们不是 API 延迟、模型推理成本或稳定生产性能证明，不能据此宣称 RRF 更快。全部细节见结果 JSON。

## 后续边界

业务检索与重排实现、配置均未改变。下一轮先冻结专用重排模型及输入格式、截断/长度规则、输出数量与失败行为，继续使用相同固定池比较，单独检查这些角色、标题、条件与多来源退步；不能给已知问题写特判。模型表现好后再讨论可配置适配器、超时回退与业务接入，不把本轮离线结论当部署许可或生产验收。

复现命令见 [README](../README.md)。完整本地产物位于 `reports/retrieval-rerank-v1/2026-11-16-frozen-r1/`，不入库；来源指纹、实现指纹、结果摘要、逐题变化和基线损失进入 Git，历史召回协议不修改。
