# 候选上限与短窗口落地

按用户逐项决策，采用 BGE 每文档上限 3 块及 256 token / 重叠 32 token 窗口，不训练或更换模型。旧的“至少快 20%、零新增损失”整体切换条件不作为本次局部优化的否决条件。协议在全量短窗口计分前冻结，完整结果及原始产物哈希见 [results.json](results.json)。

## 候选上限

同文档上限 2→3 后，相对原 BGE 在 384 份池新增 6 条标注证据、没有新增证据损失；开发组覆盖 93.75%→96.53%，首条命中 90.28%→88.89%。用户已明确接受这个取舍。`selectBge` 默认采用 3，显式调用参数仍优先；规则及异常回退仍采用原上限 2。Top 5、规则锚点 2 块和 6000 UTF-16 字符预算不变。

当前问答仍只消费一块，用户计划后续单独调整为多块消费；本轮没有修改生成层，不能把 Top 5 覆盖提升当作最终答案提升。

## 短窗口完整质量结果

两边均用已批准的每文档 3 块上限，只有窗口长度/重叠由 512/128 改为 256/32。模型权重、FP16、eager、batch8、问题/标题上限、候选池和选择约束均相同。长窗口复用冻结分数；短窗口完成全部 384 份池的计分（304 个不同问题 ID），新推理 11,412 个配对，另外 1,575 个完全相同的问题/标题/正文配对复用此次缓存。没有问题或标题 token 被裁掉。正文仍通过重叠滑窗完整覆盖，各窗口取最高原始 logit，不截掉正文尾部。

| 题组（池数）         | 平均证据覆盖：长→短 | 首条命中：长→短 | 新增证据损失 |
| -------------------- | ------------------- | --------------- | ------------ |
| 开发（96）           | 96.53%→96.53%       | 88.89%→100%     | 0            |
| 验证（48）           | 97.22%→97.22%       | 88.89%→100%     | 0            |
| 旧题回归（80）       | 95.14%→93.75%       | 84.72%→83.33%   | 1            |
| 留出原召回池（80）   | 100%→100%           | 100%→100%       | 0            |
| 留出改进召回池（80） | 100%→100%           | 100%→100%       | 0            |

覆盖和首条命中只在可回答题上计算：308 份可回答池实例中，平均证据覆盖 97.73%→97.40%（-0.325 个百分点），命中证据实例 400→399；首条命中 285/308→296/308，即 92.53%→96.10%。相对 cap3 长窗口新增证据 0 条、丢失 1 条；相对原 cap2 长窗口则新增 6 条、丢失 1 条。留出两行复用相同的 80 个问题、采用不同候选池，不是 160 个独立新问题；全部数据均为已暴露合成资料。

唯一新增损失为旧题 `kb013`：“同一条消息收到了两遍，怎么避免重复执行已经完成的工作？”长窗口保留了“消费者依靠 event_id 对应的 receipt 完成记录跳过重复副作用”，短窗口将其排到 Top 5 之外。这是真实的标注证据漏选，不能仅解释为首条顺序变化，也未通过修改标注或为该题加规则消除。原先相对规则仍遗漏的三条额度证据未修复。

## 耗时收益与决定

速度依据此前固定 12 个场景、两轮无缓存配对推理：

| 轮次 | 长窗口 P50 | 短窗口 P50 | 降幅   | 更快场景 |
| ---- | ---------- | ---------- | ------ | -------- |
| 1    | 12.033 秒  | 9.681 秒   | 19.55% | 10/12    |
| 2    | 12.024 秒  | 9.681 秒   | 19.48% | 11/12    |

这是窗口长度与重叠一起改变的模型推理收益，不是端到端请求提速或生产吞吐承诺。个别小池变慢；本次全量运行的跨轮/缓存耗时不用于计算加速比例。

按用户“小幅质量降低且明显提速即可直接采用”的授权，接受这处孤立的证据退步，落地短窗口默认值，不增加试验开关。更换其他现成重排模型仅留 TODO，不启动训练。顶层 `RAG_RERANKER` 默认仍为 `rule`；本次改动作用于 BGE 路径，没有修改业务 `.env`、重启 API 或合并 PR。

## 验证与复现边界

每份池的长、短窗口结果均通过编译后的真实 `selectBge` 回放，与独立离线选择器逐池核对集合、顺序和原始正文/标题一致，共 768 次比较。模型计分调用生产 `CrossEncoder` 和窗口实现；历史实验副本与冻结协议不修改。复现命令见 [README](README.md)，使用原始 literal 标注计分，不调用历史整体切换决策。

本轮 API 253、Node 56、Python 检索 45、工具 22、运行时 12，共 388 项测试通过；API 构建、格式、三份测试 Compose 配置及 diff 检查通过。新增运行时测试验证实际 manifest 的最小正文容量、窗口上限、重叠连续性和正文尾部完整性。未重新验证在线入库、真实权限并发、最终答案或生产负载。
