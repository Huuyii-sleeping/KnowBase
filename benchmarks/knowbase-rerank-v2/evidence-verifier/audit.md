# 剩余问题的方案验证

保持当前 BGE v2 M3、短窗口、每文档最多 3 块、Top 5。此次验证了分层选择、独立 LLM 复核和条件长窗口级联；均没有直接接入。补齐了当前参数下的真实本机 HTTP 并发、超时和恢复检查，但没有把隔离验证称作生产上线或真实业务质量验收。完整数据与原始产物哈希见 [results.json](results.json)。

## 根因与方案边界

三条现行额度证据在候选池中，但相似业务的历史条款分数更高，挤掉了正确业务的补充依据。短窗口下 receipt 去重题也把正确片段排到 Top 5 以外。这些是模型对业务归属、互补依据的评分/选择问题，不是用更多召回候选就能保证修复。

可用的通用路线包括文档与片段分层排序、LLM listwise 复核、便宜模型先筛后由更完整输入复核的级联，以及领域困难负例训练。路线成熟不代表当前模型、提示词和参数组合有效；本次保持不训练模型的约束，分别测试前三条路线。无答案判断还需要区分“与问题相关”和“足以支持答案”，不能把原始相关性 logit 当作可回答概率。

## 文档分层选择：不采用

复用当前完整分数，固定两种文档聚合：最高片段分、最高两块均分。先保留规则前两块，再按文档分组补片段，仍执行 cap3/Top5/6000，最终按 BGE 分排序。384 份池全量回放：

| 方案           | 平均证据覆盖 | 新增/丢失证据 | 首条命中 |
| -------------- | ------------ | ------------- | -------- |
| 当前           | 97.40%       | 基准          | 96.10%   |
| 文档最高分     | 97.24%       | 1 / 1         | 96.10%   |
| 文档前两块均分 | 97.08%       | 0 / 1         | 95.78%   |

最高分法补回差旅额度，但丢失发布成功不等于三路索引就绪的证据；均分法丢失列表/详情分层存储证据。没有净收益，停止，不继续调文档权重。

## 独立 LLM 复核：本轮试验不采用

使用本机已存在的 Qwen2.5 7B Q4_K_M，冻结模型 digest、温度 0、种子 42、32768 上下文和 JSON 输出约束。输入是当前 BGE Top5 与规则 Top5 的并集（最多十块，保持原文和原候选顺序），不按正确文档或金标组候选。提示词固定，明确业务、条件、版本与互补证据，模型只输出候选 ID 和是否可回答，不生成答案或改变业务问答模型。

先验证 24 道刻意选出的已暴露诊断题，其中 16 道有答案、8 道无答案，包含已知额度、receipt、跨业务、正向控制和留出题，不是随机或盲测：

| 指标               | 当前 BGE | 复核后 |
| ------------------ | -------- | ------ |
| 平均证据覆盖       | 84.38%   | 59.38% |
| 首条命中           | 81.25%   | 75.00% |
| 新增/丢失证据      | 基准     | 3 / 8  |
| 无答案题返回空结果 | 0/8      | 8/8    |
| 有答案题被清空     | 0/16     | 4/16   |

三条额度数字补回，但培训题失去历史失效依据，还丢失审批人、跨组权限、超时处理、OCR 和潜水清理职责等证据。无答案题表现好不足以抵消有答案题误拒绝。receipt 正确片段不在两个 Top5 的并集中，复核器无法补回；它的空结果不能算修复了 receipt 排名。

额外复核墙钟 P50 30.75 秒、均值 29.95 秒（包括首题冷加载），不是端到端业务耗时。24 题全部完成，没有提前停止后冒充全量；未扩展到 384 题，不接入、不继续提示词搜索。结论只针对这个模型/候选范围/提示词组合，不否定全部 LLM 复核方法。

## 条件长窗口级联：有覆盖收益，但当前不接入

固定一次探索规则：短窗口候选最高分小于 0 时再跑长窗口，保留全部候选，不做拒答判断。该 0 只控制额外计算，并不是概率或可靠置信度。协议冻结时长短分数和 receipt 问题均已暴露，因此这是探索回放，不是独立验证。

384 份池中 96 份触发二次计分，平均覆盖 97.40%→97.73%，补回 receipt 一条、无新增损失；首条命中保持 96.10%。三条额度问题仍未解决。

随后用同一真实模型、独立短/长输入配置，对六个固定场景做两轮新鲜无缓存配对；第二轮反转执行顺序，共 24 次模式执行，每次级联重新跑短窗口，并在触发时再跑长窗口。所有短/长分数与对应冻结分数完全一致。六题包括 receipt 和其他触发/不触发控制，不代表生产请求分布：

| 指标           | 第一轮   | 第二轮   |
| -------------- | -------- | -------- |
| 六题短窗口 P50 | 16.74 秒 | 15.79 秒 |
| 六题级联 P50   | 34.38 秒 | 33.74 秒 |
| receipt 短窗口 | 17.37 秒 | 18.65 秒 |
| receipt 级联   | 37.45 秒 | 43.53 秒 |

receipt 级联超过当前 API 20 秒期限，会触发规则回退；规则也没有选中该证据，因此不能声称离线补回就等于线上修复。不延长业务超时，不接入或增加开关。若以后用户明确接受几十秒延迟，需要另作完整运行与答案验收；本轮不把它列为已解决。

## 当前真实 HTTP 运行验证：通过

在隔离 loopback 端口 18089 启动当前真实 BGE 运行时，通过编译后的 `BgeHttpService` / `HybridRerankService` 调用，没有启动业务 API、连接业务数据库或修改 `.env`：

- 固定 12 个场景串行调用，全部执行 BGE，无回退，完整分数、最终 ID 顺序、正文/标题与冻结结果一致；本次串行适配器 P50 6.29 秒、最大 7.90 秒。不同运行的绝对耗时不用于相互计算优化比例。
- 一个 API 服务实例同时 6 请求，1 个执行模型、5 个返回完整原规则结果，符合实例内不排队的设计。
- 四个独立 API 服务实例共享模型，同时 4 请求，1 个执行模型、3 个因运行时忙回退，符合最终模型锁边界。
- 刻意设置 200ms 请求期限，约 203ms 返回完整规则结果；后台算子仍继续占用锁，15 次有界探测后恢复，随后模型调用与排序正常。

并发回退成功不等于模型吞吐提高。生产仍需使用实际目标机器和预期并发验收；如果要求并发请求都使用 BGE，应配置足够推理副本或实现有界动态批处理，不能把当前单路串行模型当成已支持该需求。没有擅自引入外部推理集群或部署。

## 仍需后续解决的内容

三条业务归属/补充额度问题的直接方法是带相似业务、版本和角色困难负例的领域训练，用户当前已暂缓。无训练路线可继续评测更强现成 reranker 或更强独立 verifier，但本轮结果不足以保证成功；不建议继续叠加业务词语特判。

可靠无答案过滤需要另建“相关/不相关、证据是否充分”的标注与独立验证数据，再选择阈值校准或验证器。当前只有字面证据金标，未标注片段不能自动当成负例；单次小样本 8/8 拒答也不能当作成熟拒答验收。真实用户数据尚不存在，不能伪造真实问题已验证。

当前保留短窗口和 3/5，不修改默认排序器、问答、召回、索引或训练流程。新增工具按职责拆分为策略、模型传输、断点运行、计分和隔离运行验证。API253、Node68、检索Python45、工具Python36、运行时12，共414项测试通过；API构建、格式、三份测试Compose配置及指纹/diff检查通过。
