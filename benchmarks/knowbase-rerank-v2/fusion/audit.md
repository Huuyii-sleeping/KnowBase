# 原规则与 BGE 排名融合：丢弃

本轮只验证一个成熟方法的组合：Cross-Encoder BGE 保持不变，用等权 RRF（k=60）融合原规则与 BGE 的完整候选排名。用户看到收益与退步后明确选择“丢弃融合方案，保留现有BGE候选”。没有接入生产选择器，没有增加业务开关，默认仍是 `rule`。

## 三条漏选的真实原因

对差旅、采购、培训三个原候选池各做一次真实模型推理，并用只读 forward hook 记录每个窗口的原始 logit。三池全部分数与历史记录最大差均为 0。

| 漏选证据     | 正文 token | 窗口数 | 原 BGE logit | BGE 名次 | RRF 后入选名次 |
| ------------ | ---------: | -----: | -----------: | -------: | -------------: |
| 差旅现行额度 |        353 |      1 | -2.162109375 |       18 |              5 |
| 采购现行额度 |        343 |      1 |   -1.3515625 |       17 |              4 |
| 培训现行额度 |        339 |      1 | -1.533203125 |       17 |              5 |

三个目标都是单个完整窗口，问题和标题均没有截断。对它们取最大窗口分等于原分，故不能归因于长正文窗口边界或最大值聚合。

模型正确地把本业务“旧额度已失效”条款排在第一；但另外业务的“历史规则已失效”模板也排得很高，超过了同业务的“现行额度”片段。例如差旅题中“维修派单例外”得分 1.165，而“差旅现行规则”是 -2.162。相关性更偏向题目直接问的历史条款，对配套现行数字的完整证据覆盖不足。该观察包含业务区分和补充依据排序两个因素，不能声称全是错误回答：这些数字在原参考答案之外，但本轮保留原标注，逐条报告，不修改金标。

## 单项融合试验

RRF 只使用两套名次：`1/(60+规则名次) + 1/(60+BGE名次)`，不混加原始 logit 和检索分。相同分保持候选池顺序。原规则前 2 条准入锚点、Top 5、每文档最多 2 块、6000 UTF-16 字符和原正文不变；补选与最终顺序均使用融合分。不调权重，不搜索 k，不按问题增加特判。

固定池回放共 384 份、304 个不同问题 ID，复用原 BGE 完整分数，不是重新推理 384 次。没有重新召回、没有调用生成模型。

| 来源 / 分组                    | 原 BGE → 融合证据覆盖 | 原 BGE → 融合首条命中 | 新增证据 | 丢失证据 |
| ------------------------------ | --------------------: | --------------------: | -------: | -------: |
| holdout-candidate / validation |      100.00% → 92.19% |      100.00% → 81.25% |        0 |        6 |
| holdout-default / validation   |      100.00% → 95.31% |      100.00% → 59.38% |        0 |        5 |
| v3-candidate / development     |       93.75% → 92.36% |       90.28% → 65.28% |        3 |        3 |
| v3-candidate / regression      |       95.14% → 76.39% |       84.72% → 54.17% |        0 |       16 |
| v3-candidate / validation      |       88.89% → 91.67% |       83.33% → 75.00% |        1 |        0 |

相对当前 BGE，合计新增 4 条、丢失 30 条来源–问题–证据实例。已知三条额度全部补回，但多数分组的覆盖和首条命中退步。相对原规则没有新增字面证据损失，也不能据此隐藏与 BGE 的退步。两套留出来源共享问题 ID，实例数不是不同用户问题数；这些都是已暴露合成资料，不代表生产或最终答案正确率。

按用户的新规则，没有使用旧的整体切换、零损失或固定增幅门槛裁决本次改动。助手建议丢弃，用户明确确认，因此停止，不继续搜索融合权重或参数。离线工具仅保留用于复现淘汰依据，不进入 API 运行时。

## 方法选择

继续采用“先召回，再用 Cross-Encoder 专用模型逐个评估问题–片段”的重排方向，当前 BGE v2 M3 作为质量候选保留。Sentence Transformers 的 Retrieve & Re-Rank 指南和 BGE 官方模型说明均使用这一做法。它是成熟通用方案，但没有公开使用量排名或本项目数据能证明它是所有场景的最优方案。

RRF 是成熟的排名融合工具；本轮失败的是等权融合原规则和 BGE 的这一组合，不是全部 RRF 用法。之前已测关键词/语义召回路径的 RRF，本轮是另一个位置和信号的对照，二者不能混称。

若继续处理同业务与跨业务的混淆，明确方向是专用 Cross-Encoder 的领域训练：问题–正确条款作为正例，相似措辞但业务/版本/角色不同的条款作为困难负例。那属于后续独立试验，本轮没有训练、没有宣布有效，也没有把现有评测题复制成训练集。补充证据是否必要仍应单独说明，不能靠模型训练强行修复不一致的评价目标。
