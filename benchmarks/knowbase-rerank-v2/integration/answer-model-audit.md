# 答案模型对照与引用修复

2026-11-18。**没有切换默认生成模型，PR #8 继续保持 Draft。** 3B/7B 均未通过事前冻结的“所有必要子事实正确、来源语义正确、负例拒答”开发门槛；单位测试和证据覆盖通过不代表答案质量验收通过。机器摘要见 [answer-model-results.json](answer-model-results.json)。

## 实验边界

沿用已暴露的 7 道诊断题：5 道多文档/多段落/版本/权限正例和 2 道缺失事实负例。每模型对比旧规则单块、规则多块、BGE 多块，21 个来源–问题–策略实例。实际使用 AnswerService、支持筛选、提示词和引用服务，ChatOllama 直接保留输出 Token 数和完成状态。各模型的同一题/策略提示词哈希逐一完全一致；温度0、seed42、上下文16384、输出上限512、单请求期限90秒。没有改问题、答案、候选池或为某个模型调整提示词。

模型为 Qwen2.5 0.5B、3B、7B 的 Ollama Q4_K_M，固定完整模型 manifest digest。下载权重的完整 SHA-256 已校验，模型未放入仓库。小样本只说明这组任务上的表现，不能作为一般模型排行榜。

[原协议](answer-model-protocol.json)与[v2](answer-model-protocol-v2.json)分别在 `085be0a`、`b27d2d6` 冻结。原 0.5B 验证组两次在陶艺/rule-multi 的响应流提前结束，均保留为不完整前缀；v2 增加逐题失败记录，所有题都会尝试，`complete` 只代表尝试完成，`failed_requests` 仍明确记录错误，不把失败伪造成拒答。

[v3](answer-model-protocol-v3.json)在 `8cbf61a` 冻结后才运行7B，并固定 v2 控制组原始报告哈希。v3 仅兼容评测脚本新增但未启用的 role 分支，combined 模式和输入不变。旧协议不重写，重现需检出相应提交。

| -------------------------------- | ---------------------------------: | -----------: | ------------------------------------------------ |
| 0.5B / 原组合消息                |                                0/5 |          2/2 | 多次漏答、无来源或错误回答，不作为可靠质量基准。 |
| 3B / 原组合消息                  |                                0/5 |          2/2 | 错误拒答，不采用。                               |
| 3B / 相同文字按 system-user 分开 |                                0/5 |          2/2 | 没有改善，停止该方向，不引入业务开关。           |
| 7B / 原组合消息                  | 2/5，修复分组引用格式后可恢复至3/5 |          2/2 | 有明显改善，仍有语义引用错误，不满足切换门槛。   |

`kb038` 因无支持上下文未调用模型，其正确拒答是流程结果，不是生成能力的证明。0.5B 对预先冻结的额外12道回归题（8正/4负）也尝试了36个策略实例，出现1次 provider_error；3B、7B 已在开发门槛失败，没有继续验证组，也没有用验证结果重新选模型或调提示词。

7B 的逐题语义复核：

- `kb028`：讲了数据库持久化与 publisher confirm，但没有讲清发布状态与 Outbox 的同事务保存，且标 S1；对应原文在 S3。S1 实际是重复/恢复说明。不能因同属一份文档就认为片段引用正确。
- `kb033`：100/20 MiB 及 S1/S2 均明确，模型写成 `[S1, S2]`；旧校验误拒合法的分组表达。通用归一化后可恢复 `[S1][S2]`，不更改任何来源身份。这里的3/5是对已保存原始输出的格式修复复核，不冒充重新推理。
- `training_09`：超时查真实状态、恢复核对三项均回答，来源分别正确。
- `vehicle_05`：内容正确，但逐人授权位于 S2，回答标 S3；首句 S1 也仅是归档恢复。编号合法而语义来源错误，仍判失败。
- `travel_08`：正确回答旧2500元已失效，不可据此驳回现行合格申请，S1 支持。此处不修改原 Top5 额外额度数字 gold 或它的失败结论。

## 已直接修复的代码

1. 多片段预算与完整证据身份保留，详见[上下文报告](context-audit.md)。
2. 前后引用包裹固定拒答时，清空引用和上下文。
3. 删除无来源自动补 S1；缺失、越界及混合有效/无效编号拒绝输出伪造的来源关联。
4. 对明确分组的 `[S1, S2]`、中文逗号/顿号形式做格式归一化；含非法编号的分组继续拒绝，不能把未明确的 `[S1, 2]` 猜成另一个来源。
5. 评测逐题保留原始生成与失败情况，本机 Ollama 返回200但 `done=false`/流未完成时仍判 provider_error。

第3项使缺引用的回答更容易拒答，这是一项可见行为变化，不能只用测试通过宣称可用性提高。编号检查和格式修复都不能验证结论是否真的由引用原文支持；当前端到端验收因此仍然失败，改动保留在 Draft，没有擅自合并。

## 后续边界

优先解决必要子事实漏答和逐结论的语义引用，不继续盲目加模型、调相同比例或按问题特判。需要单独验证来源对齐或结构化证据输出，再以同一份完整回归验收。当前仍为规则重排 +0.5B 默认；这表示候选未通过切换条件，不表示现有默认的答案质量已经足够可靠。

复现单个模型/分组：

```bash
npm run build
node tools/rag-evaluation/answer-model-comparison.cjs \
  benchmarks/knowbase-rerank-v2/integration/answer-model-protocol-v3.json \
  development /tmp/answer-7b.json qwen2.5:7b
```

此命令须在 `8cbf61a` 运行以匹配当时指纹；后续分组引用修复不覆盖原模型测试。完整原始回答在忽略的 `reports/retrieval-bge-context/2026-11-18-r1/`，本报告只提交小型摘要与人工复核。
