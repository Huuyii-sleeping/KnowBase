# 问答证据漏选修复与后续验收

2026-11-18。程序缺陷已修复，但本分支尚不满足端到端合并/默认 BGE 切换条件。结果汇总见 [context-results.json](context-results.json)。不修改此前冻结的协议、标注或未通过结论。

## 已修复的程序问题

1. 原问答层默认只消费一条片段。现在默认最多五条有词语支持的完整正文，总正文长度 6000 UTF-16 字符，保留原有首条超长例外；同一文档的相同正文去重，保留不同段落及跨文档来源。纯函数负责预算，grounding 继续负责支持筛选，没有新业务开关。
2. 多条件/历史对比提示词明确要求合并子事实、分别引用和区分版本；不能据此声称模型遵守了要求。
3. 拒答带前置引用（如 `[S1] 知识库中没有找到足够信息。`）曾被当作正常答案，泄露不应返回的 contexts/citations。现在仅在移除引用及句末标点后与固定拒答句完全一致时归一化，前后引用均覆盖；普通事实答案不受影响。

## 推理耗时试验

[内核协议 v2](attention-protocol-v2.json)比较相同权重、FP16、完整正文窗口及 batch8，仅改变 eager/SDPA。分别加载模型并检查真实 attention 类，交替执行顺序，串行测量 12 份池。

eager 中位 8579ms，SDPA 7551ms，减少 **11.99%**，12/12 更快；最大 logit 差 0.01171875。未达到事先冻结的至少 20% 速度门槛，因此**没有修改业务推理内核，也没有增加性能选项**。没有运行全池 SDPA 质量或宣称生产吞吐已改善。

第一版试验尝试动态切换内核，但固定版本的 XLM-R 不支持，发现后立即停止，未形成完整结果；它不是有效 SDPA 对照。v2 在 `cafc661` 修复试验方法后独立冻结，不能将第一版耗时用于比较。

## 真实生成检查及不合并原因

[生成协议 v2](answer-smoke-protocol-v2.json)使用实际 `ChatModelService`、`AnswerService` 和本机 `qwen2.5:0.5b`（temperature0/seed42），7 个固定问题 × 规则/BGE 单块/多块，28 次生成。检索池是夹具，不是在线检索或权限复测，也不是盲测。

人工逐题复核：

| 问题                           | 观察                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| kb028 事务防丢与旧版本覆盖     | 四种上下文均拒答；BGE 多块已含必要证据仍不能作答。                                                            |
| kb033 新旧上传上限             | BGE 多块回答 100/20 MiB，但历史数值只标 S1，正确来源为 S2；规则多块错误声称“没有变化”。                       |
| training_09 超时与恢复核对     | 多块包含两项证据；BGE 仍遗漏先查询真实状态，规则多块扩展无关审批/金额及操作。原规则单块也编造删除附件等内容。 |
| vehicle_05 外组逐人授权        | 规则单块给出缺乏证据的解释；规则多块变成无关规则清单，BGE 多块错误拒答。不能把多块覆盖提升当作生成无退步。    |
| travel_08 旧额度失效           | 四种方案都复述问题，未回答是否可据此驳回。                                                                    |
| kb038 收入目标、kb039 OCR 密钥 | 四种方案均拒答；这两题不代表全部负例已通过。                                                                  |

前置拒答引用的程序缺陷已修复，并在第二轮真实生成中确认 vehicle_05 的拒答返回空引用/上下文；**错误拒答本身仍存在**。没有按题目加特判、改变答案标注、下载或擅自切换生成模型。

因此先提交 draft PR，不合并当前多块默认到主分支，不强制启用 BGE。后续独立对比更有能力的中文生成模型及其引用/拒答表现，再决定默认上下文与模型组合；现有测试证明程序传证据正确，尚未证明最终回答可靠。

复核另发现，旧代码会在模型没引用时自动补 S1，这不能证明来源。后续已删除自动归因；模型必须给出属于本次上下文的有效编号，缺失、越界、混合有效/无效编号均归一为拒答，并清空引用和上下文。该检查只验证来源身份，不能验证结论的语义支持。历史生成报告保留修复前结果，后续模型对照使用修复后的完整业务流程。
