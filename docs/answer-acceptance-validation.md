# 新来源问答与业务链路验收

2026 年 11 月 23 日，冻结[当前上下文与回答方案](answer-refinement-validation.md)，使用新来源题目做第二轮验收。本轮没有调整业务代码、提示词、模型或题目标注。结论：常规问答与业务状态检查基本通过，但仍有比较题误拒、回答材料遗漏和长答案超限，不能宣称问答质量已经完全解决。

## 数据与运行范围

首次调用前冻结 30 篇合成 Markdown 文档、48 道问题及评分口径，保存语料和编译模块 SHA-256，结束时全部指纹一致。覆盖六个新业务主题，每个主题包含现行规则、例外、历史规则及两份无优先关系的冲突手册。题目共 30 道可回答、12 道信息不足、6 道冲突；包括同义表达、双来源、新旧规则及分别列值。

这些题目仍由同一助手编写，沿用相近的规则题结构，属于预先冻结的新来源合成检查，不能称为独立人工盲测。完成后已暴露，后续只能当作回归集。评分同时复核必答项、数字、条件、结论与引用，不能把状态或 JSON 通过当作完整答对。

固定候选测试使用实际编译的 AnswerService 链路，替代检索和观测存储，真实调用用户配置的 `deepseek-flash`。业务验收则创建隔离数据库和存储，通过真实 HTTP 上传、审核发布，经 Outbox、RabbitMQ 和搜索/RAG 消费者建立索引，再调用混合检索与问答接口。没有启动图谱抽取消费者，也没有验收图谱完整链路、其他上传格式或前端交互。

HTTP 使用明确的验收配置：nomic-embed-text、768 维、无任务前缀、CJK、标题章节、正文保护 2:1、Top 5、BGE v2-m3，回答最多五块、24,000 UTF-8 字节、1,024 输出 token、非思考模式。它不代表主工作区的旧进程已经切换，也不代表各项实验候选已经成为代码默认。

## 权限与发布状态

两轮 HTTP 均用独立成员账户核对：私有文档对成员不返回答案、管理员可回答；公开草稿不返回答案；发布版本由 43 件更新为 71 件后回答使用 71 件；删除后不再返回该答案。共 12 次问答均符合预期。这里验证的是接口输出行为，没有逐次导出模型请求来证明未授权内容从未进入提示词。

首次启动遇到镜像仓库连接超时，保留失败记录，使用本机已有镜像后完成。第一轮 BGE 未就绪，日志记录降级；随后恢复 manifest 固定版本的运行依赖和校验一致的模型文件，完整重跑第二轮。第二轮返回模型分数且没有 BGE 降级日志。两轮隔离容器和卷均已清理，临时模型进程也在验收结束后停止；未重启主项目。
