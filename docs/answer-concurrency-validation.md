# 完整问答链路并发基线

2026-11-23，基于已合并的 `b15d938`，测试完整问答 HTTP 链路在 1、2、4、8 并发下的质量与延迟。**256 次计分请求全部成功，但 BGE 忙碌时直接回退规则，导致必要证据落选和答案质量下降。下一步优先改善重排服务的并发调度，不以更低延迟掩盖质量代价。** 本轮只测量，不改变业务代码、配置、模型或运行环境。

## 固定数据与方法

复用[端到端修复验证](answer-e2e-fix-validation.md)的 40 篇已暴露合成 Markdown，首次调用前固定其中 32 道问题：每个主题选参数/时限、完整材料、分别列值各一题，再交替选信息不足或冲突题，共 24 道有答案、4 道信息不足、4 道冲突。原始来源、问题、必要事实与证据标签不变；这组数据适合暴露回退退步，不能当作真实用户分布或独立准确率。

各档使用完全相同的 32 题。第一轮顺序为 1→2→4→8，第二轮为 8→4→2→1，并反转题目顺序，降低固定执行顺序和总是由同一道题优先取得模型锁的影响。每档两轮共 64 次，全部 256 次；另有四次单并发预热，不计入下表。按有限波次同时发起 N 个 HTTP 请求，等待整波完成再发下一波；不是持续开放到达的压力模型，不能据此推导最大 QPS 或生产用户容量。

单个 Nest API 与单个本机 BGE MPS 运行时，使用实际默认 CJK、标题章节、正文保护 2:1、Top 5、两路各 15 个候选；nomic-embed-text 768 维、无前缀、原分块保持不变，生成仍用用户配置的 `deepseek-flash`，输入 26,000 UTF-8 字节、输出最多 4,096 token、单次 30 秒期限。测试客户端最长等待 75 秒，不改变模型期限；不自动重试失败。Langfuse 关闭，图谱库为空，不启动图谱抽取消费者。

先通过真实上传、解析、审核发布和 Outbox/RabbitMQ 建立隔离索引，等待 80 个 Search/RAG generation 激活，再运行实际 `/api/v1/rag/answer`。隔离数据库、索引和存储不使用主项目数据，用户 `.env` 仅供读取模型凭据，没有复制或输出密钥。

测试观察器对原方法各调用一次，使用同请求上下文记录召回、重排入口锁状态、BGE 请求、实际上下文、生成、HTTP 完成和模型用量。没有替换候选选择、增加在线调度、安装公开诊断接口或改变重排规则。

| ---------- | -------------------: | ------------------: | -----------: | --------------: | --------: | --------------- |
| 1          |                48/48 |               16/16 |        64/64 |      0/64（0%） |         0 | 5.57 / 10.18 秒 |
| 2          |                43/48 |               15/16 |        60/64 |    32/64（50%） |         0 | 3.82 / 7.81 秒  |

对应完整通过数为 64、58、57、56 /64。并发档中的拒答状态差异都是应判冲突却判信息不足；仍然安全拒答，但未满足冻结的状态合约，没有将其算作编造答案或完整通过。

两轮单并发均完整通过 32/32，BGE 均处理全部问题；并发组重复出现同类退步。2/4 并发的中位耗时较低，主要因为一半或更多请求跳过 BGE，不能当作相同质量下的提速。波次完成吞吐分别约 0.162、0.320、0.548、0.870 请求/秒，包含上述质量回退，且受整波等待和问题长度影响，不是服务容量承诺。

## 退步发生在哪里

每档 48 次有答案请求共标注 106 条必要证据，属于逐证据计数，不是题目准确率。

| 阶段                               |     1 并发 |     2 并发 |     4 并发 |     8 并发 |
| ---------------------------------- | ---------: | ---------: | ---------: | ---------: |
| 原始召回、资格复查、路由、合并候选 | 各 106/106 | 各 106/106 | 各 106/106 | 各 106/106 |
| 最终重排                           |    106/106 |     97/106 |     94/106 |     92/106 |
| 实际上下文                         |    106/106 |     97/106 |     94/106 |     92/106 |

没有观察到本组召回池漏证据或上下文进一步淘汰证据。全部质量失败发生在 `busy-rule` 请求：

- `wheel-03` 在三个并发档的两轮都只泛称“普通送件登记材料”和委托单，没有列出损伤照片、故障描述；完整主手册在规则重排被淘汰。六次都是部分回答，不能因为 `answered` 和引句有效算通过。
- `ferment-05`、`wheel-05`、`tactile-05` 的部分请求丢失试点甲乙记录，最终误拒；三个并发档分别有 3、4、5 次此类失败。
- 第二轮三个并发档的 `tactile-08` 丢失冲突记录，返回 `insufficient`，而冻结期望为 `conflict`。

重排入口记录表明 133 次因同一 API 实例已有在途推理而旁路；不存在模型评分失败、冷却回退、无效输入回退或 BGE HTTP 繁忙响应。把这 133 次的实际候选和选取参数交给原纯规则函数，结果均与实际回退逐字段一致。对相同候选离线计算规则结果，每档都只保留 90/106 条必要证据；实际获得的 BGE 名额补回其中一部分。因此机制证据支持优先处理忙碌旁路，而不是继续调整召回预算。

全部 123 次 BGE 评分均成功。其请求所需证据保留 197/197；133 次忙碌回退保留 192/227。两组题目构成不同，不据该分组直接推导独立模型质量因果；相同题目重复、相同请求的原始池与选择结果、纯规则回放共同用于定位。

## 耗时与可靠性

以下为同请求阶段 P50 / P95，不相加拼成总 P95；各阶段可能重叠，BGE 列仅统计实际调用它的请求。

| 阶段           | 1 并发         | 2 并发         | 4 并发         | 8 并发           |
| -------------- | -------------- | -------------- | -------------- | ---------------- |
| 关键词路       | 28 / 68 毫秒   | 26 / 73 毫秒   | 63 / 186 毫秒  | 93 / 175 毫秒    |
| 问题 Embedding | 59 / 162 毫秒  | 86 / 179 毫秒  | 218 / 564 毫秒 | 577 / 4,107 毫秒 |
| BGE 评分       | 3.76 / 4.52 秒 | 3.99 / 5.48 秒 | 4.11 / 5.33 秒 | 3.81 / 4.89 秒   |
| 生成           | 1.93 / 5.77 秒 | 1.93 / 3.82 秒 | 2.55 / 7.05 秒 | 2.07 / 10.94 秒  |

单并发时 BGE 是主要固定耗时；8 并发时本机问题向量和远程生成均出现尾延迟增长。BGE 与 Embedding 共用本机计算资源，远程服务负载与缓存不可控，这些是本次观察，不能把所有变化单独归因于某个资源。

256 次计分及四次预热共 260 次 HTTP、260 次模型调用均完成，没有 HTTP 429、传输异常、30 秒模型超时、截断或格式修正。计分回答共 497 条引句均存在于实际编号来源；逐题检查对象、单位、起算点、材料、条件和引用支持，没有在本组发现新增编造事实。计分请求用量共 416,561 输入 token、28,107 输出 token，包含缓存读取，未核对账单，不换算金额。

本轮没有注入 BGE 故障、DeepSeek 限流、断网或数据库失败；零失败不代表这些异常路径已通过真实负载验收。权限和发布版本沿用已有机制，本轮用管理员访问公共语料，没有重新覆盖并发权限变更、其他文件格式、前端或 Langfuse 上报负载。

## 下一步

优先测试 **BGE 有界等待与调度**：给忙碌请求短且有限的等待机会，限制排队长度及总等待期限，检查是否减少证据损失，同时防止长队列拖垮 P95。超时、取消及过载应有明确结果，不取消运行时模型锁，也不直接开放无限并行推理。保留原失败及完整对照题，比较相同并发负载下的完整答案、拒答状态、必要证据、回退比例和端到端尾延迟；若等待收益不足，再评估批量推理或独立扩容。

此方案尚未实现或证明有效，不能仅因单并发能答对就承诺排队后全部通过。先完成这一项对照，再决定是否处理 Embedding 尾延迟、生成限流与故障策略；本轮不提前引入缓存，避免混入权限、版本失效和重复问题比例等变量。
