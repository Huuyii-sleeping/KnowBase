# 冲突资料处理对照

2026 年 11 月 22 日，测试两种通用冲突指令。**用户复核取舍后决定全部丢弃，保留现有业务方案。** 两种方案都提升了不可判定冲突的拒答，但出现正常题误拒、错误引用或其他回归；没有把实验指令接入业务提示词。

## 问题与测试边界

只有同一对象、属性及适用条件下的结论相互矛盾，且没有明确生效、替代或优先依据，才属于不可判定冲突。不同对象、团队、环境、普通规则与明确例外不能只因数字不同就算冲突。用户只要求比较两份记录时，仍可以各自引用并列举差异。

检索排名、数值大小和上传时间不能充当业务权威依据。文档上传较晚不代表业务规则较新；软件内部文档 version 也不能直接作为不同文档之间的业务优先级。当前消费契约没有可据以进行通用确定性冲突裁决的业务规则标识、适用范围和替代关系字段，因此本轮只测试提示词能否可靠使用原文明示的依据，没有伪造优先级。

本轮不实施“非空上下文补充证据”，也不针对独立的模型条件范围理解问题添加修补规则。原有空结果回退和引用列表规范化保持不变，见[上下文设计](answer-context.md)。

## 冻结输入与方法

首次生成前冻结 24 道新合成题：8 道不可确定唯一值的冲突题、16 道有明确答案的控制题。冲突包括数值、金额、期限、岗位、许可与禁止、不同上传日期、相同生效日期；控制题包括明确替代、失效说明、签署流程优先、不同对象与环境、例外、相同含义的表达、历史查询、只比较差异以及外部附件中的伪指令。

每题执行原始及反转来源顺序，两个原文来源在每次输入中均被保留并重新编号，避免把证据被过滤当成模型冲突理解错误。冻结当前方案与第一版候选后对照；随后根据失败情况制作较窄的第二版，因此第二版使用的是已暴露诊断题。新合成题由同一助手编写，不能作为独立人工或真实用户验收。

固定 Qwen2.5 7B、温度 0、seed 42、32,768 token 窗口、1,024 token 输出上限、30 秒单次调用及一次引用修正，调用编译后的实际上下文、模型适配器、生成与引用服务。没有修改召回、重排或来源正文，没有重启运行服务。各版本分批串行执行，顺序反转是证据顺序检查，不代表已控制机器负载、缓存和执行时序。

Codex 逐题对照实际原文与来源编号复核，模型没有给自己打分。冲突题按是否擅自确定唯一值评判；只列出双方并明确无法确定的解释也计语义安全拒答。正常题检查所问结论与具体引用是否匹配，不能仅凭编号存在计正确。带“信息不足”却又给出有据结论的混合输出单独标记；若关键答案明确正确，不机械按拒答短语判错，但同一句中虚构“冲突无法消解”等事实或只引用错误来源仍不计正确且支持。

## 两种候选

第一版增加明确冲突处理流程：同对象、属性、条件的值矛盾时先查明示的生效、签署和适用范围，无依据则拒答；不按数值大小、排名或上传时间选定值，比较问题仍可列举双方。

第二版只在原有指令中加入较短约束：同一对象与条件存在不同结论且无优先关系时不擅自选择；保留比较差异问题的回答能力，不扩展其他选择流程。

## 定向结果

同一题的两种顺序分别计次：8 道冲突题共 16 次，16 道控制题共 32 次。

| 方案 | 冲突题语义安全拒答 | 正常题回答正确且引用支持 |
| --- | ---: | ---: |
| 当前业务方案 | 9/16 | **32/32** |
| 第一版明确冲突流程 | 15/16 | 31/32 |
| 第二版较短冲突约束 | **16/16** | 29/32 |

当前方案会把保存 27 天称为“较新的规定”，或因较晚上传选择 21 天；反转来源顺序也会改变是否拒答。

第一版仍有一次在无优先依据时采用某个值，且把明确生产环境规则与演练规则误判为不能回答。第二版虽然冲突题全部安全，但也新增正常题误拒，并出现批准岗位结论正确、却只引用未签署草案的情况。外部附件中的操作指令有时被误当成业务冲突，说明更强的冲突约束会放大误拒。

## 76 题实际回归

两版均用先前冻结的 40 道新题与 36 道历史题实际生成完整回归。两轮各 76 次；加上本轮 144 次定向流程，共 296 次流程调用，不含预热和流程内部的引用修正。

| 方案 | 有答案：正确且引用支持 | 无答案：最终安全拒答 | 调用异常 |
| --- | ---: | ---: | ---: |
| 当前业务方案的既有基线 | **38/46** | 29/30 | 0 |
| 第一版明确冲突流程 | 36/46 | 28/30 | 2 |
| 第二版较短冲突约束 | 36/46 | 28/30 | 2 |

第一版补对测试资料访问的前置条件，但失去住宿凭证、采购短问题的完整答案和截图凭证题，并在现行额度缺少证据时编造“0 元”。

第二版补出了境外低金额仍须审批的关键条件，另记其不恰当的信息不足开头；但失去原来正确的住宿凭证、先培训后借用和 Outbox 原因三题。原本错误选择冲突并发值的问题变为拒答，但两道其他无答案题调用超时，最终安全拒答计数下降。超时作为运行异常单独记录，不归为幻觉，也不能把不同执行时段的超时差异全部归因于提示词。

两版均没有展示同时保留正常回答与冲突安全性的可靠收益。**按用户明确决定丢弃，不修改当前运行策略，不继续围绕已暴露题堆叠提示词，也不把这次实验描述为冲突问题已解决。**

## 保留的结论

冲突处理仍是已知缺口。后续若继续，应先评估可由业务明确提供的规则标识、适用范围、生效和替代关系，再验证相应方案；上传时间、模型推测和跨文档修订号不能替代这些信息。这涉及知识管理设计，本轮未扩大实施。
