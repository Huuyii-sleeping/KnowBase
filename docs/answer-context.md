# 问答上下文与引用

项目问答默认已改为 DeepSeek API，运行配置与接入验收见[模型接入](answer-model-provider.md)，用户配置的 Flash 实测见[DeepSeek 验证](answer-deepseek-validation.md)。本文 Qwen2.5 7B 的模型质量数字是此前历史结果，不能当作 DeepSeek 质量评测。

问答消费已经完成权限与发布版本复查、合并和重排的检索结果。本轮基于 DeepSeek Flash 的实测移除消费端的词面筛选，直接按预算保留上游候选，避免旧规则命中而现行规则漏选。当前策略验收见[上下文与回答收尾验证](answer-refinement-validation.md)，新来源、实际 HTTP 和容量边界见[第二轮验收](answer-acceptance-validation.md)；本文后半部分保留本地小模型时期的历史结果。

## 上下文选择

`AnswerContextService` 默认最多保留 5 个来源，优先保留完整原文及其上游相对顺序；仅在有剩余名额时补充超长来源的原文章节，细则见下文。删除空正文及同一文档、Chunk、来源类型和正文完全相同的重复记录，不按相似度合并不同文档或片段。移除原先要求中文双字命中及英文/数字命中的二次筛选，同时删除不再使用的 `AnswerGroundingService`；没有重新查询、修改召回或扩大候选名额。

图谱路径按关系意图检索后补充文档证据；图谱无结果、没有覆盖问题实体的路径或调用失败时，保留已有的授权文档候选，不把“图谱没建关系”等同于“文档没答案”。关系题是否有依据由实际原文决定；有可用图谱路径时预留一条，再选择文档，输出按原始相对顺序。图谱固定分数不与 BGE 或规则分数再次比较。实际只有一块时不会补造证据；全部为空或放不下时直接返回信息不足，不调用模型。

## 完整输入预算

提示词包含固定规则、当前 UTC 参考日期、结构化输出合约、问题、编号来源及正文。编号在最终选择后分配，生成、引用与 API 上下文共用同一份列表。日期仅提供参考，不推导制度有效期；未来标准必须有明确适用依据，现行起始日期不保证未来值。明确公布的未来规则和覆盖所问日期的有效期仍应回答。

完整提示词（包括可能的修正指令）最多 26,000 UTF-8 字节；新增任务核对提示后，为原有正文容量保留空间。先按原有规则选择放得下的完整候选；若仍有名额，再处理单独放入也超预算的文档来源。`excerptAnswerSource` 按 Markdown 标题分节，没有标题时按空行分段；按原问题的英文/数字词和中文双字重叠选取最多 3 个相关原文区间，每段不超过 14,000 字节，按原文顺序尝试补入，并重新检查整体输入及修正指令预算。不裁剪正常来源以填剩余字节，不截取图谱路径，也不覆盖已选中的完整来源。

每个区间都是连续原文，保留该节的表格、段落和条件；不生成摘要、不跨缺口拼成一份证据。多个区间使用不同来源编号，即使属于同一 Chunk。API 的上下文及引用带可选 `contentRange: {start,end}`，表示原始候选正文的 UTF-16 半开区间，可用 JavaScript `slice(start,end)` 还原；它不是整份原始文件的字节偏移。原文引句仍必须在对应区间内逐字存在。`omittedCount` 按未被任何完整内容或区间代表的输入记录计数，重复记录也算省略，不按区间数量相减。

局部选节不保证远处的例外和隐含条件也入选；单节超长、词面不重叠、没有完整分节或剩余预算不足时仍可能没有可用补充。正常候选不受这道选节词面规则限制。收益与已知边界见[提示词三项优化对照](answer-prompt-optimization-validation.md)。

字节预算不是精确 token 计数。Ollama 路径仍申请 32,768 token 窗口，DeepSeek 使用服务端窗口；最多 4,096 token 输出，单次调用期限 30 秒，禁用自动传输重试。超时、异常、输出截断作为调用失败，不能伪装为知识不足。引句和 JSON 也占输出预算，实测十二项完整规则可以返回，不代表任意长度回答都能完成。输出预算采用依据见[遗漏、误拒与长答案修复](answer-repair-validation.md)。

## 回答状态、结论和证据

当前模型输出严格 JSON：

```json
{
  "status": "answered",
  "claims": [
    {
      "text": "报销须经主管审批。",
      "evidence": [{ "sourceId": "S1", "quote": "报销须经主管审批。" }]
    }
  ]
}
```

`status` 为 `answered`、`insufficient` 或 `conflict`。有答案时每条结论都需要证据；信息不足和无法消解的冲突必须输出空 `claims`。明确禁止、条件和例外仍是有效答案。用户要求分别列举或比较两份资料时，可以分别引用，不因值不同直接拒答；只有要求确定唯一适用规则且缺乏优先关系时才是冲突拒答。

在编号来源后追加通用任务核对提示：逐个核对必答子问，合并基本材料和“还须”的附加材料，要求结论文本本身覆盖必答项，并再次区分分别陈述与裁定唯一规则。不增加 JSON 字段、第二次模型核验或文档专用分支；随后追加主体与属性核对，要求引句支持问题对象，不把相近业务的真实数字移给当前对象；这仍是生成指令，不能当作代码已经证明语义完整。修复验证及未知子问限制见[端到端修复报告](answer-e2e-fix-validation.md)。

`parseAnswerOutput` 负责独立的纯函数校验：严格检查字段及类型，最多 12 条非空结论，每条最多 1,500 字符、引句最多 2,000 字符、整体最多 65,536 字符。每条结论至少一条证据；编号必须存在，引句必须是该来源正文的连续原文，不接受标题冒充、改写、省略号或错误来源。模型不能在结论中预写来源标记，系统只根据校验通过的证据逐条生成 `[S1]` 等引用，避免漏写编号。

`AnswerGenerationService` 协调调用和一次合约修正。结构、编号或引句不通过时，使用同一份上下文最多重新生成一次，不拼接错误草稿、不猜引句。两次失败返回信息不足，观测原因 `invalid-evidence`；服务调用异常继续抛出。正常信息不足或冲突不触发修正，不按答案字符串猜状态。

`AnswerCitationService` 仅映射实际使用的来源，并附上去重后的原文 `quotes`。API 保留 `answer`、`citations`、`contexts`，新增 `status`；有答案时返回带引用文本和对应上下文，信息不足或冲突返回固定拒答文本，引用和上下文为空。观测记录保存 `selectionPolicy=upstream-ranked`、候选与选择数量、字节预算、调用次数及实际原因，可以区分无上下文、信息不足、冲突和证据校验失败。前端类型同步，现有文本展示保持兼容。

**逐字引句能证明引文真实存在，不能证明改写后的结论一定由引文推出。** 本轮另测模型语义核验器，但它误拒正确引用，且未证明对实际答案有额外收益，因此不在线加入第二次模型拦截。数字、否定、条件、对象、时间与引用语义支持继续逐题评测。历史小模型选择不要求 JSON 和引句；本轮经用户授权用更强模型重测后，改为上述合约，不保留生产实验开关。

## 历史验证与本轮验收

以下 384 池数字对应引入空结果回退之前的历史策略，本轮没有用它们代替新策略的生成验收。使用原有 384 份已暴露合成候选池（304 个不同问题）进行固定结果回放，分别保留规则与当前 BGE 的重排输出，不重新检索或修改金标。指标是最终上下文包含标注原文证据的平均比例，不能当作回答准确率：

| BGE 固定结果的上下文策略                  | 原文证据覆盖 |
| ----------------------------------------- | ------------ |
| 旧词面过滤，最多 1 块                     | 80.03%       |
| 旧词面过滤，最多 3 块                     | 92.53%       |
| **保留词面硬过滤，最多 5 块（历史策略）** | **92.53%**   |
| 取消词面过滤，最多 1 块（未采用）         | 83.28%       |
| 取消词面过滤，最多 3 块（未采用）         | 96.59%       |
| 取消词面过滤，最多 5 块（未采用）         | 97.40%       |

当时保留词面硬门槛，因此原先 308 份有答案 BGE 池中被清空的 8 份仍未解决；76 份无答案池中仍有 55 份通过门槛。取消门槛的诊断虽然使有答案空上下文降到 0，也让全部 76 份无答案池有候选，不能据此宣称拒答能力提升。当时业务默认仍是规则重排，不能把这些历史 BGE 数字当成当前线上效果；规则固定池按当时策略的证据覆盖从 48.05% 提高到 57.31%。

真实本机 0.5B 诊断使用 18 个固定样本（6 个定向样本、原有资料前 6 道有答案与前 6 道无答案问题）。在来源模板标题清理之后的诊断中，2 例返回带有效编号的回答、4 例两次引用修正失败、7 例没有通过词面门槛、2 例模型明确拒答、3 例调用异常。编号通过也不等于语义正确；该样本不支持“最终回答已改善”的结论。诊断还暴露了流式适配器未及时结束等待的问题，随后以独立调用方计时器修复，并用不产生任何数据的假适配器验证期限。没有把修复后的单元测试冒充为重新完成这 18 例端到端验收。上下文覆盖与来源编号合约的收益应和生成模型能力分开看待，真实回答仍需继续语义评测。

当前回归测试覆盖同义表达、短中文问题、数字条件以及旧规则与现行规则同时保留，并覆盖互补证据、图谱与文档共存、UTF-8 预算、超长片段、稳定编号、无效引用、一次修正、明确拒答、调用失败及截断响应。运行：

```bash
npm test --workspace apps/api
npm run build --workspace apps/api
```

后续已完成同一上下文下的[0.5B、3B、7B 模型对比](answer-model-comparison.md)：7B 的回答与引用质量明显更好，当时确认将默认问答模型切换为 `qwen2.5:7b`；该阶段没有修改用户 `.env` 或重启服务。采用证据优先、区分禁止与信息不足、识别规则生效范围的通用提示词后，同批有答案题的回答正确且引用支持从 18/22 提升到 21/22，无答案最终安全拒答仍为 14/14（含门槛与校验兜底）；外币例外题仍误拒。数量、倒序与追加例外指令未带来进一步收益，未采用。完整对照及局限见上述模型报告。

实验输入、模型原始输出、计时日志存放在本机忽略的 `reports/answer-context/`，不作为业务代码或默认配置提交。

本轮新增 40 题、旧 36 题回归、引用真伪对照与并发验证的具体协议、结论和剩余问题，统一记录在[质量与稳定性验收](answer-quality-validation.md)。新题在首次生成前冻结，但同一助手编写的合成检查不能代替独立人工或真实用户验收。
