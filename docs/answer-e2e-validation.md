## 数据与执行范围

首次推理前冻结 40 篇 Markdown 文档、64 道问题、期望状态、必要事实和逐字证据，共八个新主题：制品签名仓、雨水回用、教学酵种、有声出版、种质观察材料、教学微电网、轮组检修、触觉教具。每主题五篇资料、八题，共 40 道可回答、16 道信息不足、8 道冲突题。覆盖表格、概念与操作含义、跨文档材料、否定与例外、历史规则、分别列值、未提供信息及未来未知值。

文档、问题和标签在两轮之间不改写。来源和编译模块指纹均在结束时复核一致；与此前 306 份问答夹具没有完全相同的问题。以上仍是同一助手编写并复核的合成数据，结构有重复，不能当作独立人工盲测或真实用户准确率。使用后转为已暴露回归数据。

每套配置分别创建隔离 PostgreSQL、MongoDB、对象存储、RabbitMQ、Elasticsearch 和 Neo4j。通过真实接口上传、解析、审核发布，经 Outbox 和搜索/RAG 消费者建立索引，等待 80 个当前 generation 激活后，调用实际 `/api/v1/rag/answer`。每轮原文均形成 40 个 Chunk，跨配置的正文和 Chunk 顺序完全一致；没有替换检索、重排、模型或引用服务。

测试入口仅在本机为同一次 HTTP 请求附加只读记录：两路召回及资格复查、合并候选、重排、图谱调用、实际上下文、生成输入和输出。观察器各调用原方法一次，不额外检索或安装调试 HTTP 接口。因此下述阶段证据确实属于实际问答请求，计时也不包含另发一次 `/search/hybrid`。

本轮没有启动图谱抽取消费者，图谱库为空；文档问答中的图谱触发逻辑仍按业务原实现运行。其他上传格式、图谱建库和多跳效果、前端交互、长期并发与生产负载不在本轮范围。

## 权限与发布版本

两套配置各做八次实际认证问答，全部符合预期：私有文档对普通成员不可见、管理员可答；团队文档同团队可答、其他团队不可答；公开草稿不参与回答；发布更新前返回 31 天，更新且当前索引激活后返回 46 天，删除后不再回答。

同时检查这些实际请求的候选、上下文和生成输入：受限场景没有携带被禁止文档的 ID 或测试暗号；更新后的生成输入使用新正文，没有把“现行周期为31天”的旧正文作为现行来源。此结论限于本组账户和时序，不代替完整权限组合及并发变更验收。

## 结论与修复优先级

1. **先修文档与图谱的路由衔接。** 普通“下载连接”问题不应被当作必须有图谱关系才能回答的问题。要保留已获准的文档证据，同时单独测试真正的关系题，避免简单去掉保护后扩大错误回答。
2. **明确实际采用的运行配置。** 当前代码默认与此前评测使用的 BGE 配置不同；本轮已配置方案更好，但不自动修改用户部署或把整套收益归因于单项参数。
3. **将跨业务错误归属与未知子问状态留作回归。** 当前引用校验能证明原文存在，不能阻止把别的对象的真实数字说成当前对象。已配置方案本轮没有出现该错误，也不能宣称彻底消失。

本轮不据结果继续调参或只重跑失败题拼接成绩。隔离 API、容器和卷均已清理，临时 BGE 进程已停止，未重启主项目。正式报告保留在本文，语料、冻结协议、运行器、原始 Trace、逐题复核及失败记录保留于本机忽略目录 `reports/answer-e2e/2026-11-23-r1/`，没有复制密钥或提交实验产物。
