# 问答模型对比

以下是本地 Qwen2.5 的历史质量评测。后续按用户选择将项目默认问答接入改为 DeepSeek API，详见[模型接入](answer-model-provider.md)。用户配置的 Flash 真实评测见[DeepSeek 验证](answer-deepseek-validation.md)，不能复用这里的准确率或延迟作为它的结果。

2026 年 11 月 21 日，在当前多片段上下文与来源编号校验下，对本机 Qwen2.5 0.5B、3B、7B 各执行 36 道题，共 108 次完整问答流程。根据对照结果，2026 年 11 月 22 日已确认采用 7B：项目默认问答模型与配置示例切换为 `qwen2.5:7b`，保留显式环境配置的覆盖能力。没有修改用户 `.env` 或重启 API；已有运行环境须在后续部署时应用新配置。

## 固定对照

24 道新合成题：单条事实、多片段综合、条件例外、相似资料干扰各 4 道，无答案 8 道；另有 12 道已暴露 BGE 固定池回归题。合计 22 道有答案、14 道无答案。新合成题在首次模型生成前固定，生成后未修改；这批数据不是真实用户数据，也不作为后续调参的独立盲测。

三模型使用相同的词面门槛、最多 5 块完整原文、24,000 UTF-8 字节预算、提示词、来源编号、一次引用修正与 30 秒单次调用期限。温度 0、seed 42、32,768 token 窗口、1,024 token 输出上限相同。调用实际 `ChatModelService` 和 `AnswerGenerationService`，没有重新召回或重排。两道无答案历史题被现有词面门槛拦截，三模型均不调用，这两题不代表模型拒答能力。

每个模型完成加载及一次不计入题目耗时的预热后串行运行。一次运行、一个 seed，未做多轮稳定性或生产并发测试；时间包括引用修正，不含预热。机器为 arm64、24 GiB 统一内存。

## 逐题复核结论

事实与引用由 Codex 对照输入原文逐题复核，没有用被测模型给自己打分。按问题所问判断主答案是否正确完整，分别检查数字、日期、否定、例外和事实对应来源；标注中未被问题要求的附加说明不作为强制完整性门槛。来源编号有效不等于语义支持，非标准措辞的拒答也按语义单独审查。

| 指标                                           |       0.5B |         3B |         7B |
| ---------------------------------------------- | ---------: | ---------: | ---------: |
| 有答案题：主问题答对                           |       7/22 |       7/22 |      18/22 |
| 有答案题：回答正确且引用支持关键结论           |       5/22 |       7/22 |      18/22 |
| 无答案题：最终安全拒答（含门槛及引用失败兜底） |      12/14 |      14/14 |      14/14 |
| 首次输出引用校验失败                           |      13/34 |       0/34 |       2/34 |
| 触发引用修正                                   |         13 |          0 |          2 |
| 最终调用异常                                   |          2 |          0 |          0 |
| 有调用题的流程耗时 P50                         |    1.28 秒 |    1.18 秒 |    3.45 秒 |
| 有调用题的流程耗时 P95                         |   10.60 秒 |    9.99 秒 |   19.88 秒 |
| Ollama 报告的模型运行内存                      | 约 0.74 GB | 约 2.68 GB | 约 5.54 GB |

耗时包含拒答和答案长度差异，3B 较快主要受到大量短拒答影响，不能据此判断其生成速度优于 0.5B。内存为 `/api/ps` 的模型 `size_vram`，不是进程总内存、峰值内存或整个应用的资源需求。模型权重均为本机已有的 Q4_K_M，固定 digest 保存在本机协议中。

## 模型对照的失败解释

0.5B 会混淆“签收次日”与“签收之日”，把停止适用的旧额度当作现行额度；有两道主答案答对却只引用部分证据，未引用真正支持例外或第二个对象的来源。引用重试与编号校验无法解决这些语义错误。

3B 的格式明显更稳定、无答案拒答更好，但较多有答案题直接拒答；另把“超过预约时间 24 小时”改成“预约后 24 小时内”，说明格式合规不等于事实正确。本轮不推荐把 3B 作为替代方案。

7B 正确回答了全部 4 道单事实和 4 道多片段题，但仍有四道有答案题误拒：

- 外币结算不论金额均须专项审批，却未能据此回答低于普通额度仍不能走普通审批。
- 已明确不允许先借后补培训，却回答信息不足。
- 新旧额度对照中已明确现行 4700 元，却拒绝选择现行值。
- Outbox 同事务及 Broker 停机保留任务的原文充分，却未能回答先入 Outbox 的原因。

这四道的所需证据都已进入模型上下文，不能归因于召回漏选。以下继续固定 7B 优化；保留来源编号校验，不因更大模型表现较好而移除验证。

## 7B 提示词优化（2026 年 11 月 22 日）

采用通用的“先找证据，再按条件回答”指令：明确禁止、前置条件也是答案；按资料明确的生效时间、停用说明和适用对象区分规则；缺少事实或冲突无法消解才拒答。不加入题目名、答案、业务额度或逐题分支。继续保留词面门槛、最多 5 块完整原文、原始顺序与一次引用修正。

同步修复拒答归一化：`知识库中没有找到足够信息 [S1]。` 等句尾标点与编号组合统一成无引用的固定拒答，避免拒答被误标为成功。它不把普通回答判为拒答，也不放宽实质回答的编号校验；`[S1-S5]` 等格式仍不合规。

使用前述固定 36 题、原文与标注，调用编译后的实际上下文、模型和生成服务。Codex 对照原文逐题复核主问题、否定条件与关键结论引用，未用模型自评分。确认轮结果：

| 指标 | 原 7B 提示词 | 采用的 7B 提示词＋拒答归一化 |
| --- | ---: | ---: |
| 有答案：回答正确且引用支持关键结论 | 18/22 | **21/22** |
| 无答案：最终安全拒答 | 14/14 | **14/14** |
| 最终调用异常 | 0 | 0 |
| 有调用流程 P50（含修正） | 3.45 秒 | 3.19 秒 |
| 有调用流程 P95（含修正） | 19.88 秒 | 22.00 秒 |

补回先培训后借用、现行额度、Outbox 原因三题；原来答对的 18 题未退步。外币审批仍误拒，不能宣称完全解决。14 道无答案中，2 道由词面门槛阻断、11 道返回规范拒答、1 道因两次编号格式失败而兜底拒答，不能把 14/14 直接解释为模型原生拒答准确率。两道触发了引用修正。

另对四道原误拒题做单项筛查（数量和顺序均使用原提示词，避免混合归因）：最多 3 块答对 1/4、最多 1 块答对 1/4、倒序答对 1/4；已采用提示词答对 3/4。额外加入“一般规则与特定例外”指令仍为 3/4，未补回剩余题。这些候选未展示超过已采用方案的收益，全部丢弃，不扩大成全批参数搜索。

这批题已暴露且用于调参，不是独立盲测，也不是真实用户准确率。新旧轮次在不同时间运行；本次单 seed、串行结果未证明速度改善或 P95 稳定变化，也未做生产并发验收。初筛轮出现异常长等待与超时，其耗时不纳入结论；单独完成确认轮，保留两轮记录。剩余应验证独立问题、真实请求下的稳定性，以及逐结论引用支持；不靠继续堆叠提示词掩盖剩余误拒。
