# 全链路观测：阶段 1 验证记录

2026-11-24，在阶段 0 的 `576facc` 基线上补齐问答观测。功能、字段及统计口径以[可观测性设计](observability.md)为准，进度以[迭代执行路线](rag-iteration-roadmap.md)为准。

## 实现范围

统一请求编号关联响应头、本地事件与 Langfuse Trace；分开记录召回内部、重排、上下文、生成与引用校验；记录 BGE 选择/回退原因、逐次模型用量、传输恢复与引用修正，并提供日志汇总命令。没有更改模型、提示词、召回/重排选择、并发门槛或时间预算。

原有检索 Span 在创建时抛异常可能绕过保护，本次将 SDK 调用全部收敛到导出适配器。正常结果、业务失败与观测失败分开处理；SDK 和日志记录异常不影响回答及其调用次数。

## 编译产物的 HTTP 检查

另外使用正式 Nest 编译产物运行真实问答 HTTP。经过真实召回协调、双路合并、重排适配器、上下文、生成 SDK、引用校验及控制器；数据库/索引/Embedding 使用小型 fixture，BGE 和模型 HTTP 服务使用本机固定响应，不加载真实模型。

| 场景                 | HTTP | 实际重排路径         | 模型调用 | 结果                                  |
| -------------------- | ---: | -------------------- | -------: | ------------------------------------- |
| 正常                 |  201 | BGE / model_selected |        1 | 回答与引用通过                        |
| BGE 运行时繁忙       |  201 | 规则 / runtime_busy  |        1 | 回答与引用通过                        |
| 冷却期间模型鉴权失败 |  503 | 规则 / cooldown      |        1 | MODEL_CONFIGURATION_ERROR，无伪造答案 |

三次请求有三个独立编号，响应头与各自日志一致，共 60 条事件；各有一个终态。日志汇总命令读取实际输出，得到三个终态、两个回答、一个故障、零缺失终态，三个模型调用，其中两个返回已知用量共 40 token、一个用量未知。两次 BGE HTTP 调用与冷却跳过符合原准入规则。记录未包含问题正文、凭据或上游私有错误。

这是接线与统计检查，不是质量评测或性能对照。原始脚本、事件、HTTP 结果和汇总保存在本机忽略目录 `reports/answer-observability/2026-11-24-stage1/`，不提交原始实验文件。
