# 问答质量与稳定性验收

本文记录本地 Qwen2.5 7B 的历史验收。后续 DeepSeek 接入状态见[模型接入](answer-model-provider.md)，用户配置的 Flash 真实评测见[DeepSeek 验证](answer-deepseek-validation.md)，不能把下面的分数当作 DeepSeek 实测。

2026 年 11 月 22 日，固定 Qwen2.5 7B，验证上下文筛选、引用支持和调用稳定性。采用两项修改：**词面选择全空时回退到上游候选；显式引用列表本地规范化**。不无条件取消词面筛选，不接入本轮的模型语义筛选或引用核验器。实际选择、预算与验证合约见[上下文设计](answer-context.md)。

## 数据与范围

首次生成前冻结 26 份合成资料、40 道新题（24 有答案、16 无答案），按不同来源领域划分 20 道开发题与 20 道前瞻性留出题。覆盖同义表达、短问题、数字条件、多块证据、禁止与例外、日期起算、新旧规则、对象混淆、缺少事实、未来未知值、资料内指令干扰和无优先级的冲突。题目、原文与事实对应来源在生成前固定，没有为通过测试修改标注。

先在开发题比较三种策略，再冻结“原词面选择 / 无词面过滤”两种方案进行留出对照。语义筛选器未进入留出测试。随后以原 36 题复查无过滤方案，再测试更保守的空结果回退。**空结果回退及引用列表修复是在查看留出结果后确定的，因此最终 76 题是回归确认，不再叫未见盲测。** 同一助手编写的合成题存在模板与作者相关性，不代替独立人工或真实用户验收。

所有质量实验使用固定的检索后候选，调用实际编译后的上下文、生成、模型适配器及引用验证模块；没有重做召回、重排、上传或业务 HTTP 请求。权限与发布版本过滤的上游契约保持不变。模型 seed 42、温度 0、32,768 token 窗口、1,024 token 输出上限、30 秒单次调用期限，以及最多一次引用修正不变；默认最多 5 块、完整输入预算 24,000 UTF-8 字节。

主答案是否充分、数字与条件是否准确、引用是否支持具体结论，由 Codex 对照冻结原文逐题复核；不是用编号命中或模型给自己的评分代替质量判断。没有把题目未问的所有附加标注都强制列为答案要求。

## 筛选策略对照

以下为引用列表修复前的单项实验。每组有答案 12 题、无答案 8 题：

| 数据 | 策略 | 回答正确且引用支持 | 无答案安全拒答 |
| --- | --- | ---: | ---: |
| 开发 | 原词面选择 | 5/12 | 7/8 |
| 开发 | 无词面过滤 | 9/12 | 7/8 |
| 开发 | 7B 语义筛选后生成 | 7/12 | 7/8 |
| 前瞻性留出 | 原词面选择 | 5/12 | 8/8 |
| 前瞻性留出 | 无词面过滤 | 9/12 | 8/8 |

语义筛选器一次判断候选能否提供所问事实，再按其选择组装原文；同义词、数字条件、否定条件仍有误拒，开发题总模型调用从原策略 16 次增加至 30 次，没有胜过无过滤，丢弃。

无过滤能补回短问题、同义表达、数字条件，以及被旧金额匹配挤掉的现行标准。但原 36 题回归中，较长的无关上下文伴随一例 30 秒超时；权限题还额外生成了“PRIVATE 仅上传者可查看”，漏掉原文明示的管理员例外。逐结论口径为正确且支持 20/22、最终安全拒答 13/14；这轮与历史回归在不同时间执行，不能把耗时差异全归因于方案。没有采用无条件取消过滤。

最终使用空结果回退：原有非空选择保持不变，仅在所有非空候选被词面筛空时恢复上游候选，复用原有去空、去重、顺序、图谱预留与输入预算。既不增加查询，也不由模型补造原文；代价是部分原来直接拒答的问题需要一次实际生成。

## 引用格式与语义核验

显式列举的 `[S1, S2]` 等列表规范化成 `[S1][S2]`，所有 ID 仍逐个检查。本地规则不猜编号、不展开范围，不接受不存在的来源，也不自动绑定第一条证据。恢复了一道内容正确却连续两次使用列表格式而被拒绝的多来源题；其他重复调用可在首次输出已有效时省掉。传输失败仍作为调用错误处理。

另在首次调用前固定 24 份回答与原文对照：正确引用、数字替换、起算日和日历单位变化、否定反转、两个有效编号互换、漏引用、旧规则冒充现行、错用对象、标识关系互换和无依据推论。真值由构造时的原文与逐项核对确定，核验模型输出不作为真值。

| 7B 语义核验器指标 | 结果 |
| --- | ---: |
| 是否支持结论判断正确 | 19/24 |
| 是否每个事实有引用判断正确 | 18/24 |
| 最终接受 / 拒绝判断正确 | 17/24 |
| 额外调用 P50 | 3.35 秒 |

它放过了起算日变化、交换来源和无依据审批条件，还错误拒绝了正确的新标准及重试标识。缺少引用的两个例子也未可靠识别。因此不接入在线拦截或自动修正，避免用不可靠的核验增加误拒；**引用的语义支持仍是未解决的能力边界**，当前格式校验没有升级成事实保证。

## 最终实际回归

采用的源代码重新构建后，完整调用 76 道新旧题，没有用回放替代这轮实际推理：

| 数据 | 有答案：修改前正确且支持 | 有答案：最终正确且支持 | 无答案：修改前 / 最终安全拒答 |
| --- | ---: | ---: | ---: |
| 新开发题 | 5/12 | 8/12 | 7/8 → 7/8 |
| 新留出题（最终已暴露） | 5/12 | 9/12 | 8/8 → 8/8 |
| 原有回归题 | 21/22 | 21/22 | 14/14 → 14/14 |
| 合计 | 31/46 | **38/46** | **29/30 → 29/30** |

新增的七道正确答案中，六道来自空结果回退，一道来自引用列表规范化。原来正确的题目未出现逐题退步。最终零调用异常，12 题使用空结果回退、1 题触发引用修正；该修正题最终由校验兜底拒答，不能计为模型原生格式合规。

新题结果只有 17/24，明显低于旧题的 21/22，说明旧小集不足以代表泛化效果。剩余问题包含：

- 旧规则命中字面但现行块没有命中时，非空选择仍可能漏掉现行值；空结果回退没有解决它。
- 模型会误拒明确禁止、受控对象与金额例外问题，也会把只适用于生产资料的禁止扩大到测试资料。
- 无法消解的同优先级冲突中，一题仍擅自采用某个来源的值。
- 来源编号有效仍不保证每个关键结论的语义支持和引用完整性。

质量耗时为一次暖机、单 seed 串行观察；不同轮次受缓存、上下文长度和系统状态影响，不用它宣称速度提升。并发测量单独记录如下。

## 调用稳定性

稳定性结果在本轮串行质量回归后单独测量，避免把并发压力混入质量对照。固定同一组双来源事实、较长 Outbox 上下文和无答案问题，每个并发档运行 8 次，总计 24 次，比较 1、2、4 并发；每档保存原始输出、调用异常、流程时间和 Ollama 状态。这里是本机适配器与问答生成服务的压力检查，不是业务 HTTP 压测或生产容量承诺。

| 并发 | 请求数 | 调用异常 | 流程 P50 | 流程 P95 / 最大值 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 8 | 0 | 3.32 秒 | 4.97 秒 |
| 2 | 8 | 0 | 4.15 秒 | 7.19 秒 |
| 4 | 8 | 0 | 7.11 秒 | 11.26 秒 |

三档中的正确事实与拒答内容一致，24 次均未出现调用异常或超过单次期限，未观察到并发引起的语义退步。因此本轮不增加限流队列或改变超时、窗口和输出上限。每档只有 8 次，P95 实际为最大值；相同问题反复运行、模型已加载，结果受缓存影响，不能据此确定冷启动、大量不同长上下文或持续流量的生产容量。全量无词面过滤实验中的一次超时也不能被这 24 次通过掩盖。

## 交付与复核

本轮保留必要的空结果回退、非空选择不变、空正文、预算、显式列表、越界编号、非法格式及不触发多余重试的单元测试；没有把实验模型选择器或核验器加入业务模块。

输入、模型 digest、实现与脚本指纹、三种策略原始输出、引用样本、逐题审查、最终 76 题和并发结果位于本机忽略目录 `reports/answer-quality/2026-11-22-r1/`。实验脚本、原始结果、生成文件与模型权重不进入业务提交。该阶段默认 7B 保持不变；没有修改用户 `.env` 或重启运行服务。

验证完成：API 318、Web 11、Node 49、Python 检索 43、工具 11、重排服务 12，共 444 项测试通过；前后端构建、修改 TypeScript 的格式检查、三份 Compose 配置校验及 `git diff --check` 通过。

后续针对冲突资料完成两版提示词及来源反序、76 题回归对照。两版都提高冲突拒答，同时带来正常题退步；用户决定全部丢弃，当前方案保留。具体结果见[冲突资料对照](answer-conflict-evaluation.md)。
