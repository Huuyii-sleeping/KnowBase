# 上下文、生成和引用收尾验证

2026 年 11 月 22 日至 23 日，固定用户配置的 `deepseek-flash`，完成上下文保留、结构化状态与证据、时间范围和语义引用核验的对照。采用移除消费端词面筛选、逐结论引用及原文引句、明确回答状态与时间/比较语义；额外模型核验器未上线。当前设计与接口以[问答上下文](answer-context.md)为准，修改前 Flash 基线见[首轮验证](answer-deepseek-validation.md)。

## 数据与评测方法

复用 76 道历史回归、24 道冲突/正常对照的正反顺序，共 124 次固定候选问答。首次新增模型调用前冻结 24 道时间题，涵盖现行标准、未公布的未来调整、未来已公布规则、过期标准、跨年有效期和未来保证；随后发现比较题误拒，在最后一轮之前新增冻结 8 道配对题：同一组无优先关系资料，分别要求“列出各值”和“确定采用值”。

所有候选仍来自冻结的检索后结果，不重新召回或重排，不绕过权限/版本契约。最终使用实际编译的 `AnswerService → AnswerContextService → AnswerGenerationService → ChatModelService → DeepSeekChatModelService`，真实调用托管 API，再经过输出解析和引用映射。只有检索与观测存储使用替身，不是完整业务 HTTP、数据库或生产验收。最终保存输入、提示词、模型配置、编译模块与运行器指纹、原始输出、最终 API 形状和逐题复核。

按原文逐题复核主问题是否完整、数字与条件是否正确、每条结论及其引用是否得到支持；模型核验器的判断不作为真值，解析成功也不直接计为回答正确。不强求题目未问的附加信息。以上均为同一助手编写并已暴露的合成回归，新题也参与了迭代，不称为独立人工盲测或泛化准确率。

## 逐项结果与采用决定

| 优化 | 对照发现 | 决定 |
| --- | --- | --- |
| 去掉二次词面筛选 | 仅改上下文的 124 次问答中，两道现行押金题恢复完整答案；无答案时的两道未来题仍有问题，说明需要分开处理模型与上下文 | 采用；仍限制最多五块及完整输入预算 |
| 结构化状态、逐结论证据和逐字引句 | 第一版 148 次输出均能解析，但有几道信息不足题仍标为有答案；统一合约及补充适用范围后改善 | 采用最终合约；纯函数检查来源与引句，系统为每条结论添加编号 |
| 时间范围 | 参考当前 UTC 日期，区分当前值、未来保证、未来已公布规则与有效期；新增 24 题最终 24/24 | 采用通用提示，不写题目或文档专用分支 |
| 比较与冲突 | 一轮业务复测中，反序的“分别列出两个值”误拒；增加比较语义规则及八道配对题，最终正常对照与比较题均正确 | 采用；冲突存在不等于无法回答比较问题 |
| 额外模型语义核验 | 48 份真假/漏引用对照中，最终接受判断正确 47/48，零错误放行、一次误拒正确引用；没有证明对最终实际答案有额外收益 | 丢弃在线接入，保留离线诊断；不让二次模型判断代替事实依据 |

语义核验夹具包含 24 份旧例和 24 份新变体，覆盖数字、单位、起算日、否定、对象、例外、来源互换和漏引用。旧夹具的 `supported` 与新审查指令对“缺引用但事实正确”的子指标定义不同，因此只对比两者均为真的最终接受决策，不将各子指标混作同一口径。误拒发生在来源明确写出 450 元的正确现行押金答案。

## 最终真实业务模块回归

最终一轮为 156 次问答，全部调用真实 API，没有调用异常、格式修正或证据格式兜底拒答。共生成 155 条结论、159 份引句引用；这些引句逐一匹配其实际来源正文，逐题审查未发现结论与原文不符。这里的引句存在性由代码检查，语义支持由本轮复核确认，不能推广成线上逻辑证明。

| 数据 | 有答案：正确且引用支持 | 无答案：安全拒答 | 回答状态正确 | 流程 P50 / P95 |
| --- | ---: | ---: | ---: | ---: |
| 原 76 题 | **46/46**（首测 44/46） | **30/30**（首测 28/30） | 76/76 | 0.83 / 1.67 秒 |
| 冲突正反顺序对照 | 32/32 | 16/16 | 48/48 | 0.72 / 2.14 秒 |

| 新比较/选值配对题 | 4/4 | 4/4 | 8/8 | 0.84 / 2.00 秒 |

运行仍为非思考模式、1,024 token 输出上限、两个并发任务、30 秒单次期限。结构与引句增加输出内容，当前样本中仍保持上述延迟；不同轮次受远程负载和缓存影响，不宣称固定速度收益。没有测量账单费用或长答案容量，JSON 和引句也会消耗输出预算。

两道旧未来题的原文只有起始生效日期、没有终止日期，其标注对“预测保证”和“现行规则持续适用”存在歧义；另有一题把“仅对503重试”下的429重试次数标为未知，实际也可推导为不重试。保留原始标签并单独注明，没有更改它们来提升成绩。最终按这些标签通过不代表这些题是真正无争议的业务真值，新增明确时间题用于交叉检查。

## 中间失败和限制

六个问答阶段分别为 124、148、148、148、148、156 次，共 872 次问答，另有 48 次语义审查。第二个结构化候选阶段保留三次调用失败，两条记录观察到约 298 秒墙钟时间，另一条约 26 秒后失败；无法仅凭现有记录确认是网络、宿主机暂停还是事件循环调度造成，不能把它们算通过或宣称所有远程调用都严格在 30 秒内结束。当前业务有独立取消计时器，完全不响应的传输在假计时器测试中验证了 30 秒期限，但 JS 计时器依赖宿主机与事件循环正常调度。最终轮和此前统一合约轮未再观察到调用失败，不等于外部服务稳定性保证。

统一合约后的首次 148 次业务复测保留一条比较题误拒；最后增加通用比较规则后的 156 次才是本次最终结果。所有阶段保留原始失败与输出，没有覆盖旧结果或只重跑失败题后拼出全对成绩。

结构化输出解决格式与状态合约，不证明模型永不误分类；逐字引句解决引文真实性，不证明模型永不把引句错误解释。仍需独立来源/人工标注和真实用户问题、长上下文/长答案及实际业务 HTTP 验收。本轮不再添加一个已观察到误拒的在线核验模型。

## 工程交付

删除不再使用的词面筛选模块；上下文只负责选择和预算，模型适配器只负责远程调用，独立输出模块负责解析与引句校验，生成服务负责一次修正，引用服务负责映射。API 新增 `status`，引用可带 `quotes`，前端类型同步；无新依赖、数据库迁移或生产实验开关。
