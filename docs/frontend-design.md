# 前端视觉与交互规范

## 设计方向

Knowbase 是面向团队的知识工作台。采用清爽的浅色界面，让文档、检索依据与知识关系成为页面主体。

- 画布：雾灰 `#F5F7F9`，内容区使用白色。
- 文字：深蓝灰 `#1E2D39`，辅助文字使用灰蓝。
- 主色：蓝绿 `#18777C`，用于主要操作、当前导航与焦点；浅蓝绿用于选中状态。
- 边框：浅灰蓝 `#E0E6EC`；状态色继续区分草稿、待审核、已发布与失败。
- 字体：品牌与英文优先使用本地 Avenir Next，中文回退到系统黑体；代码使用系统等宽字体。无需外部字体服务。
- 页面标题 27–30px，正文 13–14px，辅助信息 11–12px。色彩 token 以 `src/index.css` 为准。

文档库的连接图形对应“文档 → 知识关联 → 问答”，仅为装饰，不展示虚构统计或服务状态。文件类型以彩色文件标识辅助识别，发布状态与解析状态继续独立展示。

## 组件边界

- `AppShell`：导航、全局搜索入口、登录身份及移动导航交互。
- `PageHeader`：页面标题、说明和操作区。
- `EmptyState`：空数据说明及可选的下一步操作。
- `FileSymbol`：文件类型标识；未知类型使用中性样式。
- `ui/icon.tsx`：统一的装饰性线框图标；图标按钮通过按钮本身提供可访问名称。
- `ui/*`：按钮、输入框、表格与 Radix 弹窗等基础交互。

页面继续负责请求、筛选、分页、URL 状态和业务操作；视觉组件不访问 API。沿用 React、Tailwind、Radix，不引入新的 UI 框架。

## 响应式与可访问性

桌面使用固定宽度导航与自适应内容区；窄屏切换为抽屉导航。打开抽屉后限制键盘焦点、锁定背景滚动，支持 Escape 关闭并恢复触发按钮焦点。文档表格在自己的容器内横向滚动，不撑开页面；弹窗限制宽度与高度，内容可滚动。

全局搜索支持 Command/Ctrl + K。文档标题使用真实链接，支持键盘和新标签页访问；状态筛选使用 `aria-pressed`。弹窗提供具名关闭按钮；页面提供跳过导航链接、可见焦点和减少动态效果偏好支持。

```bash
pnpm --filter @knowbase/web dev --host 127.0.0.1
pnpm --filter @knowbase/web test
pnpm --filter @knowbase/web build
```

访问 `/documents?mock=1` 可使用项目已有的文档与图谱演示数据；该模式在当前浏览器会话保持，`?mock=0` 关闭。问答与检索仍需要真实 API；演示模式不模拟这些接口。审核队列需要管理员登录。

视觉回归应检查桌面与手机宽度下的文档筛选、搜索无结果、文档详情、上传弹窗、导航开关、问答初始状态、图谱查询和登录页。基础展示契约由 `components/presentation.spec.tsx` 覆盖，业务测试保留在对应模块。

## 知识图谱关系网络

采用现有的 [AntV G6](https://g6.antv.antgroup.com/) 作为本地图形引擎，无需把文档或图谱数据发送到第三方网站。G6 已具备力导向布局、节点拖动、曲线边和视口控制；当前需求无需另加 Cytoscape.js 或 Sigma.js。

默认“关系网络”使用 D3 力导向布局，结合查询节点的径向约束、斥力和碰撞检测，让节点分布在二维空间；“层级视图”使用 Dagre，方便按方向读取链路。圆形节点的完整名称显示在下方，查询实体使用蓝绿实色，其余实体按类别使用浅色；有向曲线上的文字表示关系类型。平行关系分别显示，不合并掉不同的关系名称。

使用 G6 标签避让行为处理重叠，优先保留节点名称和当前路径的关系标签。缩放后重新判断可用空间；完整的关系名称始终可在路径详情中读取。

标签使用独立的 `knowledge-graph-labels.ts` 行为维持屏幕字号，读相机的实际缩放值，兼容滚轮、相对缩放和路径重绘。G6 5.1.1 自带的 `fix-element-size` 把相对缩放事件的倍率当成绝对缩放，会在路径切换后让字号变小，因此此处使用基于其扩展 API 的小型行为。最小缩放允许到 2%，使接口上限的多分支层级图也能完整适配；密集图的全局视图用于总览，细节通过放大和路径侧栏阅读。

画布优先占据页面宽度，路径选择与有序路径详情放在右侧，窄屏下移动至画布下方。用户可缩放、居中、展开画布，或通过键盘选择实体查看来源。路径切换仅更新高亮，保留节点位置与缩放；查询实体、关系拓扑或布局模式变化才重新布局。容器尺寸变化通过 ResizeObserver 重新适配，不依赖窗口 resize 事件。

实现职责：

- `lib/knowledge-graph-data.ts`：合并实体、关系与来源，形成可展示数据。
- `lib/knowledge-graph-presentation.ts`：节点与连线样式、布局参数和拓扑标识。
- `lib/knowledge-graph-renderer.ts`：图形引擎加载、串行更新、视口控制与销毁；通过可注入加载器测试异步竞态和失败清理。
- `lib/knowledge-graph-labels.ts`：缩放与重绘时保持标签的屏幕字号。
- `hooks/use-knowledge-graph.ts`：连接 React 生命周期、容器尺寸和画布状态。
- `components/knowledge-graph-diagram.tsx`：画布工具栏、实体选择和详情展示。
- `components/graph-path-panel.tsx`：路径选择、关系方向和来源跳转。

画布加载失败时保留容器并提供重试。销毁或新请求到来后，旧的异步加载不会再创建画布；已经开始的渲染完成后再清理资源，避免卸载期间销毁冲突。

复杂数据的真实浏览器测试入口和结果见 [图谱组件验证](graph-validation.md)。

## 接口错误提示

HTTP 状态与响应体在 `lib/http-request.ts` 统一读取，`lib/api-error.ts` 将状态及已知的业务错误/校验消息转换为中文提示。已有页面和操作提示读取到的 `Error.message` 是转换后的文案；未知 JSON、HTML、空响应、英文异常与服务内部细节均使用统一兜底文案。保留状态码与错误类别供程序判断，不在提示中直接输出状态码或服务器原始消息。401 继续清理登录状态；登录接口的 401 单独提示账号或密码错误。

问答页以中性提示卡说明失败和下一步。网络、超时、限流及服务错误提供手动重试；权限或输入问题提示用户采取对应操作。重试保留失败问题的原始召回数量，不重复插入用户消息，也不清空用户正在编辑的新问题。仅用户点击才重新发送，不自动循环重试。

### 可复用错误工厂

`lib/error-catalog.ts` 定义稳定错误码、中文文案和恢复动作；`createApiError(code)` 统一构造错误，`requestFailure(error, operation?)` 归一化未知异常并生成展示数据。调用方根据 `action`（`edit_input`、`login`、`retry`、`refresh`、`contact_admin`、`check_result`）决定后续操作，`retryable` 表示可以提供手动重试，不触发自动请求。新增场景优先扩展错误码目录和对应测试，不在组件中判断英文错误字符串。示例：

```ts
const error = createApiError('FILE_UNSUPPORTED', { kind: 'validation' });
const failure = requestFailure(error); // 安全文案 + code + action + retryable
const uploadFailure = requestFailure(reason, 'upload');
```

上传接口对缺失文件、不支持的格式、空文件返回 HTTP 400，并附加 `FILE_REQUIRED`、`FILE_UNSUPPORTED`、`FILE_EMPTY` 错误码。前端只接受白名单中的业务码且校验对应 HTTP 状态，优先使用本地文案；旧接口继续兼容已知消息白名单和 HTTP 状态兜底。其余业务接口尚未全部改为错误码协议。

### 上传与正文解析

文件选择器的 `accept`、格式说明、选择/拖放校验、`documentsApi.create` 入口校验均使用 `lib/document-upload.ts`。支持格式与当前服务端解析器对齐：PDF、DOCX/DOC、PPTX/PPT、XLSX/XLS、HTML/HTM、PNG/JPG/JPEG/WebP、TXT、MD，扩展名不区分大小写；单文件上限为 `100 * 1024 * 1024` 字节，拒绝空文件。浏览器的 MIME 推断不作为格式依据。后端仍执行独立校验；前端拒绝音视频格式；网页 URL 使用独立导入入口。

HTTP 成功仅表示文件与草稿已经创建，上传弹窗保留结果并提供“查看文档”，按照返回的 `parseStatus` 独立展示：

| 解析状态  | 展示与后续操作                                                                                      |
| --------- | --------------------------------------------------------------------------------------------------- |
| `READY`   | 上传成功，正文已就绪，可以查看并提交审核                                                            |
| `PENDING` | 文件已保存，正文尚未就绪，稍后刷新详情或手动编辑；不承诺存在自动解析任务                            |
| `FAILED`  | 文件已保存但正文解析失败，手动编辑正文或检查源文件；不直接显示原始 `parseError`，不再次发送上传请求 |

超时、中断、断网、5xx 或无法识别成功响应中的文档 ID 时，服务端可能已经写入文档。`requestFailure(reason, 'upload')` 将这些情况映射为 `UPLOAD_UNCONFIRMED` / `check_result`，提示先查看列表核实，隐藏重新上传入口并刷新列表。当前没有上传幂等键，因此不自动重试，也不把“可以重试的 HTTP 错误”直接当成“可以重传文件”。明确拒绝的请求保留文件与表单供用户修改；上传期间阻止重复提交、关闭弹窗和替换文件。

`components/upload-dialog.spec.tsx` 使用 Happy DOM 和 Testing Library 驱动真实弹窗交互；API 边界、格式规则、错误码与上传恢复策略分别有小型测试，覆盖三种解析结果、无效文件、输入保留、连续点击和不确定结果不重传。

### 各页面统一接入

文档库、详情、问答、全文/语义/混合检索、图谱、审核队列、登录页和编辑弹窗均通过 `requestFailure` 处理请求异常。页面保留完整的 `RequestFailureInfo`，传给共享 `RequestFailure` 组件；组件根据错误动作决定展示内容，避免各页面重复判断错误类型：

- `retry`：仅调用方明确提供安全的 `onRetry` 时显示“重新尝试”。列表/详情重新读取；问答、检索和图谱重试失败时的原始问题、模式与数量，并保留新输入的草稿。
- `login`：提供“重新登录”入口；账号密码不正确属于 `edit_input`，提示修改凭据。
- `refresh`：仅提供 `onRefresh` 时显示“刷新状态”，不会把状态冲突当成重复写入的理由。
- 输入、权限及上传结果不明：展示对应说明，不提供通用重试按钮。

所有重试均由用户点击触发。编辑弹窗失败保留输入，使用原有保存按钮明确提交；审核、发布和删除操作的错误提示也经过同一归一化入口，不自动重放写请求。清空检索或图谱查询会使旧请求失效，迟到的响应不能覆盖新页面状态。图谱画布渲染异常统一映射为 `GRAPH_RENDER_FAILED`，不输出引擎原始异常；文档演示数据源同样使用稳定错误码。全局路由错误页独立在 `pages/app-error-page.tsx`，也使用共享错误组件；只读取路由异常的 HTTP 状态，未知渲染异常使用 `PAGE_LOAD_FAILED`，不显示原始响应体、状态描述或异常栈。

页面恢复流程由 `pages/page-errors.spec.tsx` 覆盖，编辑输入保留由 `components/edit-dialog-errors.spec.tsx` 覆盖；共享错误组件另有动作展示测试。
