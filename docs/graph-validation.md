# 图谱组件验证

## 可重复运行

启动前端开发服务后访问 `http://127.0.0.1:5173/graph-lab.html`，点击“运行真实引擎检查”。此页面直接使用正式的 `KnowledgeGraphDiagram`、`GraphPathPanel`、数据聚合模块及 G6 引擎，不使用假的画布或布局器。

测试数据集中在 `apps/web/src/dev/graph-fixtures.ts`，是确定性的构造数据；不连接 API，也不写入正式文档、图谱或数据库。此 HTML 是单独的开发入口，生产 Vite 构建仍只包含 `index.html`，测试页面不会出现在生产产物中。来源链接仅验证生成结果，未验证后端鉴权或文档读取链路。

## 数据与检查范围

| 场景     | 实体 | 去重关系 | 路径 | 特征                                                                    |
| -------- | ---: | -------: | ---: | ----------------------------------------------------------------------- |
| 复杂网络 |   24 |       59 |   20 | 多分支、环路、自环、双向边、平行边、多文档证据、长中文名、HTML 特殊字符 |
| 接口上限 |   61 |       60 |   20 | 每条三跳，分支不共享中间实体                                            |
| 额外压力 |   99 |      240 |   80 | 超出当前查询接口上限，用于额外探查展示边界                              |
| 单实体   |    1 |        0 |    1 | 无关系                                                                  |
| 空图     |    0 |        0 |    0 | 清空旧图                                                                |

每组数据均测试力导向网络和 Dagre 层级图：节点/边完整性、有限坐标、连线几何、节点适配画布、网络节点圆形不相交、缩放后路径切换保持坐标及视口。另测试拖动后路径更新、快速更新最终状态、销毁清理和未捕获异常。每次共 63 项浏览器引擎断言。

实际 React 组件还需要手工检查：画布点击选择、节点拖动、路径点击、缩放按钮、两种布局、展开与 Escape 关闭、长名称详情、空图/单节点切换、卸载/重新挂载。手机宽度下检查页面横向溢出及详情卡与工具栏是否遮挡。

## 2026-11-09 实测

桌面和 390px 手机视口下分别运行真实引擎检查，均为 **63 项通过、0 失败**。节点与关系数量完整，网络节点无圆形重叠，适配后节点均在画布内。桌面本机一次热启动测量中，24 / 61 / 99 节点网络的渲染与适配耗时约 48 / 79 / 185ms；该数值包括布局与绘图，不包括首次加载 G6，也不是低端设备的性能保证。

发现并修复：

- 环路中同一实体在一条路径里多次出现，导致“出现在 N 条路径”重复计数；改为按路径去重。
- 15% 的最小缩放使 61 节点层级图中 27 个节点被裁切；改为允许 2%，重新验证全部节点可见。
- G6 构造视口期间触发 transform，过早调用 `getZoom()` 报错；改为渲染完成后读取。
- 相对缩放及路径重绘后标签字号不稳定；改为读取实际相机缩放，保持标签的屏幕大小。
- 手机展开画布后，长名称详情卡被换行的工具栏遮挡；为两行工具栏预留位置。

自动化回归同时覆盖复杂数据聚合、标签行为及视口初始化时序。密集图的全局视图会隐藏重叠标签；通过放大、选择实体和路径侧栏读取细节。本次未测试真实生产数据、后端图谱查询、来源文档授权以及数千节点规模。
