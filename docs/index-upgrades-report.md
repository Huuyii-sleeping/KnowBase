# 阶段 4：受控索引升级演练

日期：2026-11-24。起点为 `6badcba`（阶段 1–3 收敛基线）。本次验证批量升级能力的功能、保存和恢复，没有升级业务数据，没有调用真实 Embedding、KG 或 MinerU 模型。代码、测试配置和证据摘要见 [验证清单](baselines/index-upgrades-2026-11-24.json)。

## 结果

预览 → 启动 → 限速投递 → 暂停/继续 → 重启与消息重投 → 三管线激活 → 汇总 → 失败重试的隔离流程通过。管理员页面支持范围预览、各管线状态、失败原因、尝试历史和清单导出；文档详情可以查看索引构建尝试。

## 真实服务演练范围

使用 PID 隔离项目中的 PostgreSQL 16、MongoDB 8、RabbitMQ 4、Elasticsearch 8.15.3、Neo4j 5；镜像 ID 固定在验证清单。正文使用真实 MongoDB，元数据与批次使用真实 PostgreSQL，投递使用真实 Outbox/RabbitMQ，索引写入与查询使用真实 ES/Neo4j。嵌入输出固定为二维非零向量，图谱返回合成事实中的固定组织与采购关系，只测试交付协议。

合成资料是“海岚制造采购与交付规则”，包含工作日交付周期、检验记录和验收后 30 天账期；局部编辑样本含 5 个标题章节。另造 52 份草稿验证跨页扫描。资料由测试在临时存储内生成，标题和事实没有被标为真实业务资料。

| 场景                 | 可核对结果                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 预览分类             | 可重建、未发布、缺正文、需重新解析各 1 份；无投递、模型或激活副作用；旧策略未知保持 unknown                            |
| 分页扫描             | 52 份元数据，首个清单页 50、第二页 2；正文逐份读取                                                                     |
| 限速、暂停、重启     | 每条管线间隔 60 秒；即时第二次投递被拒；两个调度实例共享锁；在途上限 2 生效；取消只影响 pending                        |
| 旧索引替换与重复正文 | 2 份相同正文产生 6 个管线任务，6 个 generation 激活；旧 RAG generation 退出可见集合；ES 全文/向量和 Neo4j 关系均可回查 |
| 变更、删除、缺正文   | 3 份计划资料分别被修改、删除、移除正文，最终 3 份跳过；模型输入 0；删除项仍在历史清单                                  |
| 图谱失败与重试       | KG 自动尝试 3 次后死信，人工修复后仅 KG 再尝试 1 次；全文/向量成功 generation 未改变，人工重试额外向量输入 0           |
| 运行中断             | 未完成尝试保留记录；新 generation 恢复，旧尝试标 interrupted                                                           |
| Worker 强杀          | 子进程持 receipt 事务并保存尝试后 SIGKILL；真实队列重投原事件，新进程完成，新旧 generation 可追踪                      |
| 配置漂移             | 调度暂停，执行端在模型调用前拒绝，恢复操作返回配置不匹配                                                               |
| 激活账本失败         | 事务回滚时 head 不切换，任务不假成功                                                                                   |

| 构建期间编辑         | 抽取期间变成新版本，旧 generation 激活被拒，任务跳过                                                                   |
| Outbox 事务失败      | 插入事件后故障回滚，任务仍 pending、事件数 0，下一轮可安全投递                                                         |
| 管理 HTTP            | 非管理员 403，非法范围/分页/操作 400，start 返回 202，此时 activeDocuments 仍为 0                                      |
| 局部编辑             | 初次 Embedding 输入 10；同文档下一版本局部编辑，新增输入 2；新版本三条索引均激活，旧计划当前有效数降为 0               |

重复正文的两份文档各产生 1 个向量输入和 1 个图谱输入，总量分别是 2、2，说明缓存不会跨文档授权边界合并。局部编辑的 10 → 2 是不同修订在缓存开启后的实际替身输入数，不是同输入的解析准确率比较，也不是耗时提升比例。

## 修复记录

首轮真实演练揭露两项实现错误：升级事件 UUID 与既有回执字符串比较需要显式类型转换；TypeORM 的 PostgreSQL UPDATE 返回值需读取 affected count，而非把整个返回元组当作返回行。均已修复，补单元回归后重跑完整演练通过。空白正文 fixture 也调整为符合真实 MongoDB schema 的输入。

一次质量工具测试误与 `nest build` 并行，dist 清理造成 module-not-found；构建结束后按依赖顺序重跑 13 项通过。旧失败日志保留在忽略目录，没有用失败轮次计数拼接成功结果。

## 复现与边界

```sh
pnpm --filter @knowbase/api build
DELIVERY_TEST_PULL_POLICY=never node --test --test-concurrency=1 apps/api/test/indexing/upgrades.test.cjs
pnpm --filter @knowbase/api exec vitest run --maxWorkers=2
pnpm --filter @knowbase/web test --maxWorkers=2
node --test apps/api/test/ingestion/quality/*.test.cjs
```

运行 CJS 演练和质量工具前必须完成 API 构建，不能在这些命令运行时重新清理 dist。Compose、数据库、队列和模型设定见测试源码及 [升级指南](index-upgrades.md)。原始日志在忽略目录 `reports/index-upgrades/`，摘要文件记录校验值，生成资料和服务数据不提交。

本阶段首版的结束条件在上述合成资料和隔离服务范围内达到。真实模型质量/成本/吞吐、生产语料规模负载、完整浏览器链路和 main 联合契约验收没有被本报告覆盖。存量正文重建可用不表示原件复杂解析问题已全部解决；批量重新解析、音视频、向量空间迁移均不属于此次交付。
