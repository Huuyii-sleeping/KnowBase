## 固定策略与配置

| 项目            | 本次基线                                                                                                  |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| MinerU 部署依赖 | `deploy/mineru/requirements.txt` 固定 4.2.3；默认 Flash；历史报告按实际 producer 记录                     |
| 解析任务策略    | `evidence-pipeline-v6:xlsx-native-v1:html-native-v1:pdf-tables-v1:documents-only` 加解析/VLM 配置生成指纹 |
| 分块策略        | `structure-v4:<size>:<overlap>`；模板为 1000/150，分块对照为 180/256/512/1000、overlap 0                  |
| 正文与证据      | `structured-markdown-v1`、`table-v1`、`evidence-v1`；具体来源语义见能力文档                               |
| 向量            | 文档 ID + 最终模型输入 + 指纹；指纹绑定提供方/端点/模型/显式修订/维度/预处理版本                          |
| 持久复用        | `EMBEDDING_MODEL_REVISION` 模板为空，默认不启用；本轮恢复对比使用固定替身修订                             |
| 模型预算        | 模板批次 32 条/24000 字符、并发 2、超时 60 秒；对照使用 2 条、并发 1                                      |
| token           | 标准 OpenAI 模型按 cl100k、最多 8191 token；Ollama `truncate:false`，不套用错误 tokenizer                 |
| 原生 XLS        | 独立 Python 环境的 xlrd 2.0.2，不恢复公式表达式、不执行重算                                               |
| 视觉增强        | 模板 `IMAGE_ANALYSIS_MODE=ocr`；真实视觉评测待后续阶段                                                    |

以上是源码、配置模板和特定评测的条件，不是读取用户私有 `.env` 得到的生产运行配置。模型换权重或输入预处理变化必须更新修订/指纹；更换向量空间需要与查询侧协调，不能仅重建一部分后混查。

## 与最新 main 的衔接审查

已执行 `git fetch origin main`，核对远端 **`b15d9380e77668a027f68c9700baff7fae52aa3b`**。本地 `main` 仍是旧起点，不能用它代替最新主线。此表来自源码比较，尚未合并或运行组合版本。

| 衔接点       | 最新 main                                                          | 本分支                                                         | 后续集成必须保留的规则                                                   |
| ------------ | ------------------------------------------------------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------ |
| RAG 模型输入 | `RagChunkTextService` 输出正文和 `retrievalText`，含文档标题/章节  | 结构 Chunk 输出 `content`、`embeddingText`、来源；二者当前相同 | 保留原文引用语义及结构来源，再由唯一输入组装层生成检索文本，避免重复标题 |
| ES 结构      | `retrieval_text`、正文/检索文本 CJK 子字段、更新后的 reader/writer | `ingestion` 来源元数据、分批/字节预算/refresh 屏障             | 合并两套字段与写入约束，不能用一边覆盖另一边；新增字段后需要重建         |
| Embedding    | `embedQuery`、文档/查询前缀配置                                    | 文档批次、token 检查、校验、文档内缓存和恢复                   | 保留查询能力；校验实际带前缀输入；前缀/预处理进入缓存指纹                |
| 文档查询     | `findPublishedByIds` 等检索再鉴权接口                              | 解析任务、质量、证据响应扩展                                   | 同时保留检索接口与正文可选字段，当前版本/权限过滤不能退化                |

因此，**本分支基线收敛与 main 集成是两个状态**。当前可继续准备阶段 4.1 的预览能力；把本分支合入主线或实际批量升级前，必须完成上述接口整合与组合版本的全量/一致性/检索证据回归。此次没有修改 main、召回、重排或 Prompt，也没有把单分支测试称为联合验收。

## 升级前提与剩余工作

新增数据库能力依赖 PostgreSQL 006–009 和 MongoDB 003/004，已有库需按能力指南执行迁移，新库用 init。迁移文件摘要随清单固定；先迁移再启动 Worker。异步候选闭环需要 `INGESTION_ASYNC_ENABLED=true`，XLS 原生证据与 VLM 按需配置。详细命令分别见 [解析任务部署](mineru-ingestion.md#配置与部署)、[证据配置](multimodal-ingestion.md#接口与配置)、[构建恢复部署](index-build-recovery.md#升级与回滚)。

剩余项按固定顺序处理：main 集成作为发布前置；阶段 4 的预览、调度、界面和演练；阶段 5 的真实视觉/复杂资料质量；阶段 6 的 HTTP/Worker/界面联合验收、负载和回滚演练。跨页合并、断裂行、多栏顺序、任意动态图表、旧 XLS 公式恢复、提取中途持久检查点仍按明确边界管理，不能因本轮整理而标为已解决。音视频继续暂停。

本轮没有运行存量重建、重新解析、数据删除、迁移到用户数据库、推送或合并。阶段 4 的下一交付单仍为 **4.1 升级预览**。

## 复现入口

从实现基线检出后安装锁定依赖，先构建 API，再执行编译产物相关测试。低资源环境建议限制 Vitest worker，Docker 套件串行执行；只清理测试自身的项目与卷。

```bash
pnpm install --frozen-lockfile
pnpm --filter @knowbase/api exec vitest run --maxWorkers=2
pnpm --filter @knowbase/api build
pnpm --filter @knowbase/web test --maxWorkers=2
pnpm --filter @knowbase/web build
node --test apps/api/test/ingestion/quality/*.test.cjs
DELIVERY_TEST_PULL_POLICY=never node --test --test-concurrency=1 \
  apps/api/test/ingestion/persistence.test.cjs \
  apps/api/test/ingestion/tasks.test.cjs \
  apps/api/test/ingestion/formats.test.cjs \
  apps/api/test/delivery/reliability.test.cjs \
  apps/api/test/indexing/consistency.test.cjs
```

没有本地镜像时按环境允许拉取后执行，不使用 `never`。分块对照命令见 [分块评测](chunk-evidence-quality.md#评分与可复现对照)，真实解析质量与保存验证命令见 [业务解析评测](ingestion-quality.md#生成与复现)。JSON 清单只是固定摘要与验证索引，不会自动启动服务或触发升级。
