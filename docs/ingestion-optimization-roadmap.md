# 文档入库优化执行路线

更新日期：2026-11-27。本文件是本分支后续工作的执行顺序和验收清单，替代最初基于 `955f1e1` 的规划。具体实现、配置和历史评测仍以各能力文档为准，不在这里重复维护。

## 目标与边界

目标是让一份资料从上传到可检索形成完整、可核对、可恢复的链路，并让已有文档能受控升级到新策略。

```text
原件/网页快照
  → 解析与结构化
  → 正文、证据、资源保存及回读校验
  → 必要的人工核对、采用
  → 审核发布
  → 结构分块
  → 向量生成 / 图谱抽取
  → 完整索引写入与激活
  → 检索证据核验
```

本分支负责前置数据和构建链路。召回、重排和 Prompt 由另一分支负责；联合验收固定其版本，只验证数据交付和效果，不在本分支调整它们。

当前采用 **MinerU OCR 主流程，不新增额外视觉大模型依赖**。按用户决定，VLM 的模型优化、截断治理和默认启用均暂停；既有实验接口保持默认关闭，历史报告保留。流程图关系和图表数值理解不作为当前自动解析的承诺，保留原图供核对。

当前范围为文档、表格、图片和静态网页，格式与限制见 [多格式解析](multimodal-ingestion.md#输入能力)。音频、视频按用户决定暂停，见 [TODO](media-ingestion-todo.md)。本路线不承诺一次解决所有复杂 PDF、动态网页或视觉理解问题。

## 执行纪律

1. 同时推进一个阶段，阶段内部按下面的交付单逐项完成。发现其他问题登记到对应阶段，不直接转向新主题。
2. 一个交付单围绕一个业务能力，包含实现、针对性测试、文档和验证结果；涉及的提交保持可独立审查。
3. 缺陷先落成可重复的失败样本，再修改规则；标准答案不传给解析器或分块器。用过的保留样本不能继续声称是未见资料。
4. 每阶段固定比较输入、代码与配置指纹。区分功能正确性、真实服务可靠性、真实模型质量和性能，分别报告。
5. 结束条件未达到时保持该阶段未完成，报告剩余失败项；不以测试总数替代质量结论。
6. 新增问题只有阻断当前阶段的正确性、权限、保存或恢复时才插入处理，并记录原因。

## 阶段 4：存量文档的受控批量升级

先让阶段 2–3 的成果覆盖已有 Markdown；本阶段首版只批量重建索引。需要重新解析原件的资料另行列出，不与索引重建混合执行。

### 4.1 生成升级预览

**要做的事：**

- 管理员按文档范围和发布状态选择目标，分页扫描，不一次读入所有正文。
- 固定本次目标策略，包括分块策略及预算、Embedding 指纹和相关索引配置；明确当前策略信息缺失的旧文档。
- 为每项记录 documentId、version、contentId、目标配置指纹和是否可执行。显示将重建、需重新解析、缺正文、未发布等分类及数量。
- 预览不发送任务、不修改正文、不切换索引。初始预览与实际执行之间文档发生变化时，在执行前重新检查。

**交付物：** 可持久化的升级计划、逐文档清单、管理员预览接口。

**验收：** 相同快照和目标配置得出相同分类；草稿、删除、正文缺失不会误进入执行；预览没有投递副作用。只有摘要未知时标为未知，不能猜测旧索引采用了什么策略。

### 4.2 实现可靠的批量调度

**要做的事：**

- 从已预览的计划创建批次，复用现有 Outbox 和 Worker，不创建另一套索引构建协议。
- 分离“批次投递速率”和“单文档模型并发”，有界投递，避免一次灌入全部任务。
- 持久化批次项目状态，并将项目关联到实际消息、构建尝试和 generation。重复启动或重复投递有幂等约束。
- 每项执行前复查版本、contentId 和发布状态；变更后记为跳过，不能用旧计划覆盖新文档。
- 暂停停止投递新项目；已投递项目继续按现有协议完成。取消未投递项目不撤销已经激活的索引。
- 重启后恢复计划进度；失败项可单独重试，已完成项不重新加入。

**交付物：** 批次状态存储、调度服务、暂停/继续/重试接口及迁移。

**验收：** 注入重启、重复执行、消息重复、数据库/队列故障、并发修改和删除后，项目可追踪、无覆盖、无无限重复计算；模型和队列并发受限。

### 4.3 汇总真实完成状态并提供操作界面

**要做的事：**

- 显示总量、待投递、执行中、成功、失败、跳过及重试结果；计数以项目状态推导，批次汇总与明细一致。
- 区分“任务已提交”“构建结束”“当前版本索引已激活”。成功必须关联本项目标配置、版本及实际激活结果。
- 每条管线分别展示，部分完成不能标整份文档成功；激活结果不确定时单独显示。
- 文档详情展示已有索引阶段接口；管理入口展示预览、启动、暂停、继续和失败重试。
- 给维护人员显示可操作的失败分类；不向页面泄露模型原始响应、正文或凭证。

**交付物：** 批次查询接口、文档索引状态展示、批次管理页面与导出清单。

**验收：** 权限测试、前端状态测试和隔离真实服务测试通过；HTTP 202 不被显示为完成；旧尝试不冒充当前版本。

### 4.4 演练并验收首版批量升级

固定一组合成存量文档，包含旧分块产物、重复正文、局部编辑、未发布、缺正文，以及执行中被修改和删除的情况。

记录扫描数、可执行数、成功/失败/跳过数、每管线激活结果、实际模型输入量和重试量；用真实数据库、队列、ES/Neo4j 验证恢复，用真实模型单独记录耗时。没有真实模型运行时，仅报告替身输入量与可靠性，不生成模型提速结论。

**阶段结束条件：** 预览 → 启动 → 限速投递 → 重启恢复 → 汇总 → 失败重试完整演练通过；用户能在界面定位失败文档；版本与删除保护不退化；升级操作说明和报告可复现。

本阶段之后，已有文档可以受控使用新分块和构建策略。批量重新解析的候选调度若有需要，在此机制稳定后单列交付；任何重新解析仍保留核对、采用和审核流程，不自动替换已发布正文。

## 阶段 5：OCR 与复杂资料的定向质量优化

阶段 4 完成后进入。先做质量基线，再根据失败分布选择修复项，避免再次按格式零散扩张。

### 5.1 建立独立的复杂资料评测集

- 保留已有业务档案，并新增此前未参与调试的资料：流程图、统计图表、截图、扫描表格、跨页表格、多栏文本、公式与图片混排。
- 每类分别标注可见文字、金额/符号/单位、对象关系、来源位置和应判未知的内容。表格继续核验行列归属及合并关系。
- 用户目前没有真实业务资料，使用明确标为合成的资料，必要时补充来源和使用条件清楚的公开样本；不能标为生产验证。
- 开发集与保留集分开，并记录样本来源、摘要和修改历史。

**交付物：** 数据清单、标注、评分器、错误分类报告。

2026-11-24 已交付：[复杂资料质量基线](complex-document-quality.md)、[独立语料](../benchmarks/ingestion-complex/README.md) 与 [诊断报告](complex-document-quality-report.md)。本轮未修改生产解析器；原生诊断不代表默认 MinerU 的质量，5.2 已运行真实服务及本地模型，见 [模型对照报告](complex-document-model-quality-report.md)；5.3 仍未完成。

### 5.2 调用真实模型，比较 OCR 与视觉增强

- 固定 MinerU、视觉模型及其修订、提示配置和输入预算，比较同一输入的 OCR 基线与 OCR + 视觉描述。
- 按类别记录文字/关键值正确性、关系正确性、无依据新增事实、未知项处理、来源匹配、耗时、请求量和可计量成本。
- 模型描述继续与原始 OCR、原图、原生单元格分开保存。验证描述是否进入预期 Chunk 和索引，以及能否回看原图。
- 如果没有可用真实 VLM，继续完成样本、评分与协议工作，但该交付单保持待验证，不用模拟响应代替质量验收。

**交付物：** 真实模型对比报告，列出成功、失败及不确定样本。

2026-11-25 已交付：[真实模型报告](complex-document-model-quality-report.md)。本地 Qwen3-VL-2B 已跑通，图表和流程图有补充收益，但发现单位错误、虚构箭头及输出截断；隔离保存/分块/真实向量/暂存索引已验证。5.2 的对照交付完成，阶段 5 的质量门槛未达到，不能据此默认启用 VLM。

### 5.3 优先完善 OCR 与表格，暂停额外视觉模型

2026-11-26 用户明确选择不继续接入额外视觉模型。5.2 实验与历史缺陷保留，不再作为必须完成的优化项，不要求通过 VLM 质量门槛后才能进入阶段 6。

执行顺序：

1. **5.3.1 扫描表格行列归属与保存。** 将明确对齐的 OCR 代码表转换为可核对的单元格，保留标题、列顺序、空白、负号和单位；歧义结果保留原文和原图。已实现并通过真实服务、新合成样本及隔离保存验证，见 [OCR 表格报告](ocr-table-quality-report.md)。标题跨列合并关系仍不猜测，所有恢复结果需核对。
2. **5.3.2 OCR 适用边界与发布核对。** 将图表语义遗漏、金额/否定事实风险列入端到端验收清单；无足够证据时提示核对原件，不编造替代值。规则不能证明所有 OCR 内容正确，也不承诺用文本规则自动恢复图片关系。
3. **进入阶段 6 的完整链路验证。** 优先上传 → OCR → 候选核对采用 → 审核发布 → 索引激活 → 来源回看 → 删除清理；固定检索版本验证交付，不调整另一分支召回、重排及 Prompt。

每轮只处理报告中明确的一类问题；旧保留集仅作回归，再调优使用新资料。关键金额、单位、符号、否定和空值不得在后处理及保存中静默改写。无需增加模型或服务来满足上述要求。

**本阶段收敛条件：** 当前 OCR 适用格式、可核对的候选、保存/分块交付证据和未解决边界有明确记录；不再将完整图表语义理解列为当前承诺。不能把“无需 VLM”表述为“OCR 已能理解所有图片”。

动态网页、独立视觉向量索引、旧 XLS 公式重算、任意 PDF 表格自动重建均不是本阶段默认交付。

## 阶段 6：完整链路验收与上线交付

### 6.1 完整用户链路

通过实际 HTTP API、Worker 和页面完成：上传/网页快照 → 解析 → 原件与证据回读 → 低质量核对 → 采用 → 审核发布 → 索引激活 → 固定检索版本下查到预期证据 → 回看来源 → 删除清理。

抽样覆盖各格式路由，重点覆盖多页 PDF、旧 Office、原生 Excel、含图片文档和静态网页。比较保存前后事实、来源和资源摘要，不只断言接口返回成功。检索验证记录事实证据是否可交付；归因到召回、重排或 Prompt 的问题登记给对应分支，不在这里混改。

2026-11-27 首轮真实 HTTP/Worker 与页面检查见 [完整链路报告](ingestion-acceptance-report.md)，包括 OCR 适用边界提示、候选身份隔离、HTML 表格预览及正文图片授权。检索响应尚未直连页码/bbox 自动定位，不将原件可读等同精确引用跳转。

### 6.2 故障、权限与负载

- 故障：解析超时、模型返回非法结果、保存失败、部分 bulk 失败、进程强杀、重复任务及激活提交结果不确定。
- 竞争：编辑、重新解析、候选采用、重建和删除交错时，不能覆盖新版本或复活已删文档。
- 权限：当前正文、历史正文、候选、证据、对象票据、索引状态和批量管理分别验证。
- 负载：先固定文件规模、页数、正文大小、并发和部署资源，再记录吞吐、阶段 P50/P95、内存、队列积压和数据库连接占用；不先承诺提速比例。
- 只有负载证据表明 receipt 长事务/连接池成为瓶颈，才引入独立索引任务租约或额外吞吐改造。

2026-11-27 已完成 **6.2.1 故障与并发交错验收**：新增 10 个 HTTP/Worker 固定场景及既有 36 项真实服务回归通过，见 [故障恢复报告](ingestion-resilience-report.md)。原生 TXT 与确定性模型替身只用于状态验收，不代表模型质量或负载结论。**6.2.2 首版基础设施容量基线**已验证：固定 16/64 KiB TXT、并发 1/4/8，共 120 份完整链路与清理通过，见 [容量报告](ingestion-capacity-report.md)。并发 4→8 未增加吞吐而尾延迟升高；尚无持续连接池等待证据，本轮不重构 receipt。真实 OCR/模型、长期稳定性与生产容量仍待独立压测，下一交付为 **6.3 发布与回滚演练**。

### 6.3 发布与回滚演练

统一验证 PostgreSQL 迁移、MongoDB 索引、应用配置、独立解析服务和模型修订；先小批验证，再逐步扩大目标范围。回滚方案区分应用代码、策略、正文候选和索引空间，保留可核对的原件与历史数据。

同一向量空间才能复用和混查。若更换模型空间，需要独立设计索引和查询侧切换，本路线不把它伪装成普通分块重建。

**阶段结束条件：** 有一份固定版本、固定数据和固定配置的联合报告，包含格式/事实质量、保存/权限、构建/恢复、性能和升级结果；阻断项已处理，已知限制有明确产品行为；发布与回滚步骤演练通过。

## 每次交付如何汇报

后续每次结果固定使用以下顺序：
