# 文档入库流水线优化路线

本文保留基于 `955f1e1` 制定的完整路线，不表示所有阶段均已完成。当前实现、配置与升级规则集中维护在 [ingestion.md](ingestion.md)，后续实施应先确认 main 的最新接口变化。

当前已落地合成语料基线、可选正文结构/来源契约、主要格式解析修复、结构分块及共享产物、Embedding 批次/校验/文档内复用、ES 分批与 refresh 屏障、资源补偿清理和阶段日志。后续已接入 MinerU v4、旧 Office/静态 HTML/图片入口、质量诊断、异步解析/租约恢复/任务状态和可选旧完整 generation 回收，实际边界见 [mineru-ingestion.md](mineru-ingestion.md)。真实服务及清晰合成扫描件已实测；音视频、URL 导入和复杂信息的下一阶段设计见 [multimodal-ingestion.md](multimodal-ingestion.md)，生产语料检索质量仍需独立实测。

## 目标与协作边界

本分支负责提高进入检索系统的数据质量，并降低重复构建的时间和模型成本：

```text
原始文件 → 格式解析 → 结构化正文 → 分块 → Embedding / 图谱抽取 → 暂存索引 → 激活
```

另一个对话负责召回、重排和 Prompt 组装。两边通过正文、Chunk 和索引契约协作。当前阶段保持检索响应中 `documentId`、`version`、`chunkIndex`、`content` 等既有字段的含义，新增来源定位字段优先采用可选字段。改变分块算法会改变 Chunk 边界和序号，不能把 `chunkIndex` 当成跨重建稳定的引用。

已有的发布边界、Outbox 投递、generation 激活、版本检查和删除保护继续作为约束，详见 [pipeline.md](pipeline.md)。性能优化必须保留这些保证。

## 已确认的现状

| 环节     | 当前实现                                                        | 优化切入点                                                                      |
| -------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 解析契约 | `ParsedDocument` 返回 Markdown、资源、解析器名称及 warnings     | 缺少统一的正文块、来源位置和解析策略版本                                        |
| PDF      | 根据文本坐标拼接行；把页内普通行和表格行分别汇总后输出          | 文表穿插顺序可能改变；无文本页面仍返回 `ready=true`；需要检测质量不足           |
| Office   | XLSX 已保留工作表，PPTX 已保留页，DOCX 转为 Markdown            | 将已有格式边界转换为统一来源定位，逐格式补充回归样本                            |
| 上传     | 请求内等待解析，随后写 MongoDB 与 PostgreSQL                    | 先测量大文件延迟；原文件和正文已有补偿清理，提取资源的失败回收仍需完善          |
| 分块     | 字符递归切分，默认 1000 字符、150 字符 overlap，返回 `string[]` | 不理解代码围栏或表格，不携带标题路径和来源位置；缺少中文句界优先策略            |
| 构建     | RAG、KG 各自读取 Markdown 并分块                                | 缺少可复现的分块产物与策略标识，尚未共享同一份分块结果                          |
| 向量生成 | RAG 一次向适配器传入全部 Chunk，仅检查返回条数                  | 应用层缺少显式的资源上限、向量完整校验和跨重建复用；底层 SDK 的批处理需单独测量 |
| ES 写入  | 全部 Chunk 组成一次 bulk；完整成功后激活 generation             | 大文档需限制单批体积；失败重试会重新计算向量；旧批次尚无自动回收                |
| 评测     | 现有检索 qrels 是文档级，另有索引一致性测试                     | 文档命中不能证明具体答案片段完整，需要增加入库质量与证据片段标注                |

上述是代码行为与风险分析，不是性能测试结果；尚无数据证明哪个阶段耗时最多。

## 执行顺序

按“基线 → 契约 → 解析 → 分块 → 构建效率 → 运行治理”推进。先保证信息未丢失，再优化知识单元，最后优化计算和写入。每一步以独立、可回滚的 PR 交付，不将整个路线合成一次改造。

### 0. 建立基线与回归语料

准备六种格式的小型固定样本，并覆盖中文长段落、嵌套标题、文表穿插、长表格、代码、多页 PDF、无可提取文本的 PDF、损坏文件和重复内容。用公开或合成内容，避免把内部文档提交到仓库。

标注预期正文顺序、关键事实、表头与数据的关系、页码/工作表/幻灯片位置。检索样本以原文证据范围或关键事实标注，不能只绑定旧算法产生的 Chunk ID。

记录解析、分块、Embedding、索引写入和激活的独立耗时；记录输入字节数、正文长度、Chunk 数与长度分布、模型输入量、构建峰值内存、失败阶段。固定模型和配置后保存冷构建与重复构建基线。阶段指标和阈值根据基线确定，不预先承诺没有测量依据的提速比例。

**交付与验收：** 可重复执行的样本和报告；同一输入、同一配置产生可比较的结果。复用现有评测工具，新增报告放在忽略的生成目录。评测使用固定的召回、重排和 Prompt 版本，避免另一分支的变化干扰归因。

### 1. 补齐中间数据契约与策略标识

先定义最小可用契约，再逐个解析器接入：

- 解析结果增加可选的有序正文块，区分标题、段落、列表、表格、代码和资源引用；块携带来源位置。Markdown 仍用于展示和旧数据兼容。
- 来源位置按格式表达：PDF 页码、PPTX 幻灯片、XLSX 工作表及行范围；Markdown 偏移注明是规范化正文的位置，不能声称等同于原文件字节位置。
- Chunk 产物保留正文、标题路径、来源范围、顺序、内容摘要和分块策略版本；明确正文与用于 Embedding 的上下文文本的区别。
- 分离文档修订号、解析策略、分块策略、Embedding 模型配置和索引 generation。只改算法或更换模型也必须能识别并触发适当重建。
- 旧内容没有结构信息时明确降级为 Markdown 分块；用户手工编辑 Markdown 后，不沿用旧文件解析生成的定位信息。

**交付与验收：** 小范围类型与存储扩展、兼容性测试、序列化与定位规则测试；旧内容可读取，旧查询调用仍有效。契约优先落在生产方，检索和 Prompt 是否展示这些元数据由另一分支接入。

### 2. 提高解析保真度与失败可恢复性

优先修已发现的问题，再逐格式补齐结构信息：

1. PDF 保留文表穿插顺序，识别无有效正文及部分页面缺失，提供可区分的质量警告；先修正常文本 PDF，再用真实复杂版式样本决定是否替换解析器。
2. MD/TXT 校验编码及空正文；DOCX 保留标题、列表和表格；PPTX 保留幻灯片内顺序；XLSX 保留工作表、行范围及表头关系。每个格式分别交付与验证。
3. 将解析异常、降级成功、需要人工处理的低质量结果区分开，明确哪些结果可以进入审核。扫描件提示需要 OCR，不能只凭生成的占位文字判为解析成功。
4. 完善主解析器失败、fallback、正文持久化失败时的提取资源回收；仅删除当前尝试创建且未被采用的资源，失败清理应可重试。

**交付与验收：** 格式专属 fixtures 验证内容顺序、表格、定位、warnings、失败状态和资源清理；审核流程不放行失败或无效的解析结果。

OCR 作为此阶段后的独立扩展：先统计扫描件占比，再决定引擎、语言、成本与人工校验。OCR 质量不足时必须可见，不能把引擎成功返回等同于识别正确。

### 3. 升级结构感知分块

采用确定性的结构分块作为第一版，先不引入额外 LLM 调用决定切点：

- 按标题层级和正文块组织内容，携带标题路径；控制标题上下文的预算，避免重复标题挤占正文空间。
- 段落优先保持完整，长段落优先按中英文句界切分，最后才进行长度兜底。
- 表格按行分组，每组保留表头；普通大小代码块保持完整，超长代码按行拆分并补齐围栏。明确超长单行、单元格等不可再分单元的处理规则，兼顾可读性和模型硬限制。
- overlap 限制在相同语义范围内，避免机械拼入上一章节或另一个工作表的内容。
- 校验 size、overlap 等配置；区分字符预算和模型 token 限制，不能把字符数直接解释为 token 数。
- 分块逻辑保持纯净，不访问数据库或调用模型；单独的产物存储负责持久化。RAG 与 KG 复用同一份有序、不可变分块产物，再分别决定各自模型输入的批次。

**交付与验收：** 关键事实没有遗漏；标题归属正确；表格组有表头；代码片段可辨认；相同输入与策略输出稳定。补充答案片段覆盖、无用重复和长度分布报告，并在固定检索版本下复测 Recall/MRR/NDCG。结构测试通过不等于检索效果已经提升，发布需附对比报告。

### 4. 降低 Embedding 与索引构建成本

在分块契约稳定后再引入复用，避免缓存错误的中间产物：

1. 应用层显式限制 Embedding 的单批条数、输入量和并发；限制超时和重试，与已有消息重试形成统一预算。验证每个向量的数量、维度与有限数值，避免错误向量进入 ES。
2. 根据“实际 Embedding 输入摘要 + 模型配置指纹”复用向量。指纹包括提供方、模型/修订、维度及输入预处理策略；模型名不变但内容可更新时，要求显式配置修订标识。
3. 文档内先去重，同一文档内容未变化时复用；跨文档复用需明确授权域、保留策略与删除语义。复用计算产物不表示复用文档权限、索引记录或可见指针。
4. ES 按条数和字节体积分批写入，所有批次成功且查询可见后才激活。任一批失败仅清理本次 generation，旧完整 generation 继续服务。
5. 仅修改标题、标签和权限时，按实际模型输入判断是否需要重算向量；即使复用向量，仍写入当前修订的索引批次并通过现有版本检查。
6. 记录构建使用的解析、分块和模型配置。切换 Embedding 模型时评估存量与查询向量的空间兼容性；即使维度相同，也不能混用不兼容模型。通过新索引构建与查询配置协调切换完成迁移。

**交付与验收：** 重建命中缓存时减少实际模型输入；修改相关文本或模型配置会失效；超大文件请求体与并发有上限；部分 bulk 失败、空批次、乱序、删除与激活不确定性等现有一致性测试继续通过。

本阶段先用批次控制和向量复用减少重复工作；逐 Chunk 增量索引属于后续优化，不能绕开完整 generation 的激活条件。

### 5. 完善运行状态、异步解析与回收

依据阶段 0 的数据决定并发与异步化的优先级：

- 对解析、分块、Embedding、写入与激活记录阶段状态、耗时、错误、配置指纹和重试次数。业务发布状态与索引就绪状态分开，用户能区分“已发布”和“正在构建/构建失败”。
- 如果解析占据上传请求的主要延迟，使用已有 Outbox/Worker 模式异步解析。先持久化原文件、PENDING 文档与任务，再由 Worker 完成解析；覆盖进程退出、重复任务、重新解析、编辑或删除竞争及失败恢复。
- 大规模提高并发前，评测 delivery receipt 长事务占用的连接数；只有确有瓶颈时再引入带续租和 fencing 的任务租约，避免单纯扩大 Worker 数。
- 给不可见旧 generation、失败暂存数据、过期计算缓存和无引用资源设计保留期。索引回收须同时检查任务状态、激活竞争和在途查询宽限期，不能仅按“当前未引用”删除。

**交付与验收：** 可定位每个文档失败在哪一阶段；故障恢复可重试；重启与并发删除不恢复旧内容；回收不会误删活动构建或查询需要的数据。涉及存储与队列的行为用隔离真实服务测试补充验证。

## PR 与验证安排

推荐按以下顺序拆分，每一项可以独立审查；格式修复和运行治理继续按能力细分：

| 顺序 | PR 范围                                    | 前置条件                  |
| ---- | ------------------------------------------ | ------------------------- |
| 1    | 入库样本、阶段计时与基线报告               | 无                        |
| 2    | 来源定位、策略版本与可选结构契约           | 1                         |
| 3    | PDF 顺序与质量检测修复                     | 2                         |
| 4    | Office / 文本结构补齐及解析资源清理        | 2；逐格式交付             |
| 5    | 结构分块规则、配置校验与内容回归           | 2–4；支持旧 Markdown 降级 |
| 6    | 分块产物持久化，RAG/KG 接入同一产物        | 5                         |
| 7    | Embedding 有界批次与向量校验               | 1；可提前开展，不依赖缓存 |
| 8    | 模型指纹、向量复用与失效规则               | 5–7                       |
| 9    | ES 分批写入与一致性回归                    | 7；保留现有激活协议       |
| 10   | 阶段状态、按需异步解析、任务治理与安全回收 | 前述稳定后按测量结果细分  |

每个 PR 先运行对应模块测试，再运行 [development-guide.md](development-guide.md#testing-expectations) 中的完整检查。触及索引分批写入、激活、删除或回收时，运行真实服务的 `test:index-consistency`；触及投递或任务恢复时运行 `test:delivery`。数据结构变更附迁移、重建与回滚说明，格式和分块变更附固定语料的前后结果。

本路线的第一个实施任务是 PR 1：建立可衡量的基线。规划文档本身不需要运行完整应用测试；应检查差异、文档链接和格式。
