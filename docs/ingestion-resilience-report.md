# 入库故障恢复与并发一致性验收

2026-11-27，阶段 **6.2.1：故障与并发交错验收**。在真实 HTTP、Worker 及六类隔离存储/队列服务之间建立可重复的暂停和失败注入，确认已有状态保护能够跨应用进程生效。本轮未发现需要修改生产业务逻辑的新缺陷；新增验收工具和证据，阶段 6.2 的负载与容量测试仍待执行。

## 固定条件与范围

使用 PostgreSQL、MongoDB、RabbitMQ、RustFS、Elasticsearch 和 Neo4j 的独立 Compose 项目，真实 JWT 登录、HTTP 上传/编辑/核对/发布/删除、Outbox、回执、解析 Worker、索引 Worker、检查点和 generation 指针均走生产实现。

输入为小型合成 TXT，使用真实原生文本解析器。向量生成是固定非零的 768 维测试向量；图谱模型返回空实体/关系，图谱数据库仍实际写入与删除文档/Chunk。这些替身用于稳定安排状态交错，不测模型准确率、召回效果或性能，不调用 MinerU、VLM 或外部模型服务。

故障只在独立测试子进程的内存适配器中注入，通过父子私有 IPC 控制；生产主入口、依赖注册和 HTTP API 没有增加故障开关。测试入口没有 IPC 通道时拒绝启动。解析租约固定为 3000 ms，解析最多 3 次，pipeline 重试基准 200 ms；检查点重启使用同一数据库、队列、资源和 JWT 配置。

## 新增的 HTTP/Worker 场景

| 场景                   | 注入或交错                                     | 必须观察的结果                                                                                     |
| ---------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 重复解析命令           | 已完成任务收到不同投递身份的新命令             | 命令回执完成，任务尝试与解析次数仍为 1                                                             |
| 正文写入后失败         | Mongo 正文真实保存后抛异常                     | 第二次尝试采用新正文，废弃正文和证据已清理，最后只有一份采用正文                                   |
| 提取后采用失败         | 持久检查点已建立，第一次 apply 前抛异常        | 尝试 2 次，原件读取和解析均只有 1 次                                                               |
| 连续解析异常           | 解析边界连续抛异常 3 次                        | 达到预算后 FAILED，无采用正文，不能提交审核                                                        |
| 检查点后进程强杀       | apply 前暂停，对整个 API/Worker 子进程 SIGKILL | 租约到期后启动新进程，直接复用同一个检查点；新进程原件读取与解析均为 0                             |
| 解析与手工编辑交错     | 解析已返回但未交付时暂停，先提交新正文         | 旧任务变 stale，完成旧投递后新正文和 v2 修订保持不变                                               |
| 候选采用与编辑交错     | 已读取候选后暂停，先提交编辑，再恢复采用       | 事务内重新检查版本，采用返回 409，不覆盖新正文                                                     |
| 解析与删除交错         | 解析返回前暂停，先删除，再恢复 Worker          | 旧投递结束后文档 404，无迟到正文，原件删除，三条索引指针均为删除标记                               |
| 激活实际提交后丢失响应 | RAG 指针已真实 COMMIT，返回前暂停并抛异常      | 已提交数据仍可查询，记录 activation_unknown，重试激活新 generation；旧完整批次保留等待正常宽限回收 |
| 索引激活与删除交错     | ES 已暂存，activate 前暂停，先删除再恢复       | 不复活指针、文档或检索结果；暂存 Chunk 和正文清除                                                  |

暂停点由 IPC 命中通知确认，随后才执行另一操作；不靠随机 sleep 猜测竞争顺序。对 SIGKILL 等待真实租约时间到期，并由应用启动时的维护恢复任务。解析次数、原件读取次数分别在实际调用边界计数，不能用任务尝试数代替读取量。

通用删除断言同时检查 Mongo 正文/证据/资源登记/分块及向量缓存、ES 文档及 Chunk、Neo4j 文档/Chunk，以及 RustFS 原件和已登记资源键。TXT 本身没有提取图片，因此本轮不把空资源列表计为图片补偿质量证据；含图片资源的正常交付仍见 [完整链路验收](ingestion-acceptance-report.md)。

## 既有回归及结果

另外重跑已有真实服务集成 **36/36**，覆盖：发布事务与 Outbox 回滚、断开并恢复 RabbitMQ、已确认消息重发、回执幂等、毒消息预算/死信、租约恢复、取消/编辑/删除保护、检查点失效、三条索引的旧版本构建与删除竞争、真实 ES 部分 bulk 失败、回收宽限及构建进度等。这组测试部分业务适配器使用替身，不能把每项都称为完整 HTTP 或真实模型测试。

最终新增 HTTP/Worker 场景 **10/10** 通过；故障控制与既有验收工具 **3/3** 通过。API **507**、Web **256** 项测试及两端构建通过；Web 保留既有大包提示。Compose 合并配置、变更文件格式和差异检查通过。各隔离环境最终移除自身容器和卷，未使用用户已有数据库。

[机器基线](baselines/ingestion-resilience-2026-11-27.json) 保存案例结果、源码/工具/编译产物、日志摘要与失败记录。完整本地日志和报告在忽略的 `reports/ingestion-resilience/`；不提交密码、登录令牌、原始服务凭证、模型或生成二进制。

首次新增场景有 7/8 通过，其中“编辑期间解析返回”测试错误地等待旧结果进入 apply；生产代码已在更早的任务进度更新处拒绝 stale 任务，所以该等待超时。改为等待旧投递回执完成，再核验正文和修订后通过，保留首次失败报告。随后加入实际 COMMIT 响应丢失和解析期间删除场景，并按解析、并发、索引职责拆分套件，逐步加强清理与读取次数断言，最终版本完整重跑。另外修复了测试日志随旧子进程退出而关闭的问题，最终日志包含强杀前后两次应用启动及后续索引场景；不影响原来的业务状态断言。

## 复现

先构建，输出目录必须不存在；仅运行故障控制工具测试时不需要外部服务。

```bash
pnpm --filter @knowbase/api build
node --test apps/api/test/ingestion/resilience/fault-control.test.cjs \
  apps/api/test/ingestion/acceptance/*.test.cjs
RESILIENCE_OUTPUT=reports/ingestion-resilience/new-run \
DELIVERY_TEST_PULL_POLICY=never \
node --test --test-concurrency=1 apps/api/test/ingestion/resilience/scenarios.test.cjs
DELIVERY_TEST_PULL_POLICY=never \
node --test --test-concurrency=1 \
  apps/api/test/delivery/reliability.test.cjs \
  apps/api/test/indexing/consistency.test.cjs \
  apps/api/test/ingestion/tasks.test.cjs
```

`never` 要求本机已有测试镜像，否则使用默认 `missing`。本套件不需要运行模型服务，也不需要真实业务资料。不要让测试入口消费生产队列；默认创建自己的项目、随机端口和账号。复现不能与 API build 同时运行，避免编译目录在子进程运行中被删除。
